# 07 一键导入（tab-import）

> 页面位置：`static/index.html` → `<section id="tab-import">`；前端函数 `loadImportTab`、`impPreview`、`renderImpPreview`、`impCommit`、`impReset`；后端 `ImportController`、`DataImportService`、`ImportParser`。
> 数据链：券商导出文件 → 预览（不写库）→ 确认 → `t_trade` / `t_account_daily` / `t_position`(+`t_position_daily`)。**这页替代手工逐条录入，导入错一次比手录错一天更贵，所以强制先预览。**

## 1. 这页回答什么（不回答什么）

回答：

- 券商导出的成交流水、每日资金、当前持仓，能不能一次入库？
- 系统把我的哪一列认成了「成交日期」「代码」「数量」？有没有识错？
- 哪些行会写进去、哪些行因为重复被跳过、哪些行有问题？
- 导入完数据去了哪里，统计页为什么立刻变了？

不回答：

- 行情数据（收盘价、板块涨跌）——仍需每日复盘或外部数据源。
- 计划、纪律、复盘文本——这三类没有标准的券商导出格式。
- 亏损原因分析——导入只保证流水完整，判断仍在统计页。

## 2. 三种导入类型

| 类型 | 用途 | 入库表 | 重复处理 |
| --- | --- | --- | --- |
| 成交流水 `trades` | 补历史/当期买卖记录 | 逐行调 `TradeService.record`，写 `t_trade`，同时维护 `t_position` 与 `realized_pnl` | 按「日期+代码+方向+价格+数量」查重，默认跳过 |
| 每日资金 `daily` | 补每天的净值与现金 | `t_account_daily` upsert | 同一账户同一天覆盖 |
| 当前持仓 `positions` | 用券商对账单校准持仓数量与成本 | `t_position` 按代码覆盖；有最新价时同时写 `t_position_daily` | 同一账户同一代码覆盖 |

**为什么成交不直接写库**：成交会触发加权成本与已实现盈亏的连锁计算。导入必须走 `TradeService.record`，否则会出现「导入的成本价」和「手工录入的成本价」两套算法，卖出盈亏永远对不上。

**为什么持仓只覆盖不回推**：持仓是「某天的结果」，丢失了买卖过程；用它反推成交会凭空造出流水，把原因分析和计划内外统计污染掉。

## 3. 接口与调用时机

| 动作 | 接口 | 参数 | 说明 |
| --- | --- | --- | --- |
| 上传文件预览 | `POST /imports/preview` | `file`、`type`、`accountId` | 只解析、只查重，不写库 |
| 粘贴预览 | `POST /imports/paste` | `type`、`accountId`、`text` | 从 Excel 直接复制即用 |
| 确认导入 | `POST /imports/commit` | `type`、`accountId`、`defaultReason`、`skipDuplicates`、`rows` | 服务端重新逐行校验后再写 |
| 自动同步状态 | `GET /imports/sync/status` | — | 监听目录、定时时点、上次结果、最近记录 |
| 手动同步 | `POST /imports/sync/run` | — | 立即扫描下载目录并导入，不必等定时任务 |
| 账户下拉 | `GET /accounts` | — | 默认跟随顶部全局账户 |

前端状态只有三块：`impState.type`（当前类型）、`impState.preview`（最近一次解析结果）、`impState.busy`（防重复点击）。切换类型会清空预览，避免把流水按持仓提交。

## 4. 字段口径

### 4.1 成交流水

| 字段 | 识别关键词（部分） | 必填 | 口径与异常 |
| --- | --- | --- | --- |
| 成交日期 `tradeDate` | 成交日期、交易日期、发生日期、成交时间、委托日期、日期 | 是 | 支持 `2026-11-05`、`2026/11/5`、`20261105`、`2026年11月5日`、Excel 序列号；无日期整行报错 |
| 代码 `symbol` | 证券代码、股票代码、证券编码、代码 | 是 | 去引号、去等号、转大写；代码为空整行报错 |
| 名称 `name` | 证券名称、股票名称、证券简称、名称 | 否 | 只用于展示，可空 |
| 方向 `side` | 买卖标志、买卖方向、委托方向、操作、业务名称、交易类型、方向 | 是 | 买入/证券买入/买/B/BUY → `BUY`；卖出/证券卖出/卖/S/SELL → `SELL`；数量为负也判为卖出 |
| 价格 `price` | 成交均价、成交价格、成交价、委托价格、价格 | 是 | 缺失时用「成交金额 ÷ 数量」反算；去千分位、¥、元；≤0 报错 |
| 数量 `quantity` | 成交数量、成交量、成交股数、股数、数量 | 是 | 正数；负数自动转正并把方向改成卖出 |
| 费用 `fee` | 手续费、佣金、印花税、过户费、规费、交易费用 | 否 | **多列相加**：佣金+印花税+过户费 都识别时合计为费用；空按 0 |
| 理由 `reason` | 买入理由、交易理由、备注、摘要 | 否 | 空则用页面上的「默认理由」（默认「批量导入」） |
| 成交金额 `amount` | 成交金额、成交额、发生金额 | 否 | 仅用于反算价格，不单独入库 |

干扰列会被主动排除：市值、盈亏、金额占比、比例、可用、冻结等，避免把「盈亏金额」认成「成交金额」。

### 4.2 每日资金

| 字段 | 识别关键词 | 必填 | 口径 |
| --- | --- | --- | --- |
| 日期 `tradeDate` | 交易日期、日期、对账日期 | 是 | 与成交同一套日期解析 |
| 总资产 `equity` | 总资产、资产总值、资产合计、总权益、净资产、账户资产 | 是 | 必须 ≥ 0；这是净值曲线的唯一来源 |
| 可用资金 `cash` | 可用资金、可用金额、资金余额、可用余额、可取资金、可用、现金 | 否 | 缺省 0。漏现金会让净值偏低、回撤算错 |
| 备注 `note` | 备注、说明 | 否 | 只做记录 |

### 4.3 当前持仓

| 字段 | 识别关键词 | 必填 | 口径 |
| --- | --- | --- | --- |
| 快照日期 `snapshotDate` | 快照日期、持仓日期、对账日期、日期 | 否 | 缺省为今天 |
| 代码 `symbol` | 证券代码、股票代码、代码 | 是 | 同上 |
| 数量 `quantity` | 当前持仓、持仓数量、股票余额、股份余额、持仓股数、数量、持仓 | 是 | 必须 > 0；为 0 的票应已清仓，不导 |
| 成本价 `avgCost` | 摊薄成本价、参考成本价、持仓成本价、成本价、平均成本、成本 | 是 | 缺失时用最新价兜底；与手工录入的加权成本口径一致（含买入费用） |
| 最新价 `closePrice` | 最新价、最新价格、现价、市价、收盘价 | 否 | 有值时写持仓快照，并按「市值 ÷ 当日或最近净值」算仓位占比 |
| 名称 `name` | 证券名称、股票名称、名称 | 否 | 覆盖持仓表的名称 |

## 5. 表头识别规则

1. 在前 10 行里逐行打分，选「命中必填字段最多」的一行当表头；命中阈值 = min(3, 必填字段数)。
2. 列匹配优先级：完全相同（100+）> 包含关键词（60+）> 被关键词包含（20+）。同一列不会重复分配。
3. 找不到表头时退化为**固定列顺序**兜底，并在预览里给黄色警告，提醒你核对列识别。
4. 文本文件自动判断编码：UTF-8（含 BOM）优先，严格解码失败退 GBK；分隔符在前 5 行里统计逗号、制表符、分号，取出现最多的。
5. 单次最多 2000 行；超过请按月拆分。

## 6. 预览怎么读

| 元素 | 含义 | 判读 |
| --- | --- | --- |
| 数据行 | 解析出的有效数据行（不含表头） | 应≈券商导出的行数；明显偏少说明表头没认对 |
| 可导入 | 校验通过、且库里没有的行 | 这个数字才是点确认后真正会写入的行数 |
| 已存在 | 与库里成交重复的行 | 同一份文件导过，或增量文件与旧区间重叠 |
| 有问题 | 缺必填、数量≤0、价格≤0、日期非法 | 合计行/备注行出现 1~3 行属正常，不用改；真实数据行要回 Excel 修 |
| 列识别 chips | 「字段 ← 原始列名」 | 出现「（未识别）」的必填字段，说明该列没匹配上，导入会整行失败 |
| 行状态徽标 | 可导入 / 已存在 / 有问题 | 鼠标悬停有问题行可看具体原因 |

**关键原则：统计数字对不上就先别点确认。** 写错一批流水的修复成本，远高于重新导一次。

## 7. 去重与覆盖规则

- 成交查重键 = `tradeDate | symbol | side | price | quantity`（价格用去尾零后的字符串）。
- 查重不是「存在即跳过」，而是**计数消费**：库里同键有 2 笔、文件里也有 2 笔，这 2 笔都会被判为重复；文件里有 3 笔则多出的 1 笔可导入。这样同价同量的真实分笔成交不会被误杀。
- 页面「重复记录」下拉：
  - `跳过`（默认）：已存在行不写库，只写新行。
  - `仍然导入`：不做去重，适合你确认券商流水与库里记录本就不同（例如补录了不同账户）。
- 每日资金：同一账户同一天 `upsert`，后导覆盖前导，不会出现两条净值。
- 当前持仓：按 `(账户, 代码)` 覆盖数量与成本，不会删掉其它持仓。

## 8. 分析案例

一份 **486 行**的成交流水：

- 表头在第 1 行，识别出 8 列：成交日期、证券代码、证券名称、买卖标志、成交均价、成交数量、手续费、备注。
- 3 行是「合计」「本页小计」「备注：数据仅供参考」，被标为**有问题**。
- 12 行与库里 9 月的成交重复（同一份文件之前导过），标为**已存在**并跳过。
- 最终提交 471 行，写入 471 行，跳过 12 行，失败 0 行。

导入后抽查：

1. 去「记成交」按日期升序看第一笔与最后一笔，价格、数量、费用是否与券商一致。
2. 去「账户与资金」看持仓只数与市值是否与券商对账单一致。
3. 去「统计总览」看区间已实现盈亏是否与券商的「平仓盈亏」大致对齐（差额应只有费用口径差）。

**反面案例**：把「合计」行也强行导入，会凭空多出一笔几十万股的成交，加权成本瞬间被拉到异常值，之后所有卖出盈亏全错——这正是必须先预览的原因。

## 9. 数据前提与限制

- 文件支持 `.xlsx`（POI 解析）、`.csv`、`.txt`；`.xls` 老格式不支持，请另存为 xlsx。
- 表头必须包含关键词；列顺序无所谓，多余列会被忽略。
- 成交流水导入按日期**升序重放**，保证先买后卖；若文件缺卖出记录，持仓会偏高，需要补齐区间再导。
- 成交理由为空时统一填默认理由，方便日后在「亏损原因分析」里单独筛出来补写。
- 导入不校验行情，代码大小写/空格不一致会被当成两个标的；导入后可在标的分析里核对代码。
- 当前持仓导入不产生成交；如果持仓与流水长期对不上，优先补流水，再用持仓校准。

## 10. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示「未识别到表头」 | 前 10 行没有包含关键词的行，或表头是合并单元格 | 在 Excel 里整理成单行表头再导，或改用粘贴 |
| 预览全是「有问题」 | 必填列没认对（例如成交日期认成了备注） | 看列识别 chips，按关键词改列名后重新解析 |
| 中文变乱码 | 文件是 GBK 但内容里混入了非法字节 | 另存为 UTF-8 CSV 再导；系统已优先尝试 GBK 兜底 |
| 「已存在」数量异常多 | 同一份文件重复导入，或增量区间与旧数据重叠 | 确认后选「跳过」即可，只有新行会写入 |
| 导入成功但统计页没变 | 其它页签缓存了旧数据 | 切到统计页点「拉取统计」，或切换一次账户触发全量刷新 |
| 持仓数量比券商多 | 文件缺卖出记录 | 补齐卖出日期区间后重新导入 |
| 现金为空导致净值偏低 | 每日资金文件没有可用资金列 | 补上「可用资金」列，或导入后在每日复盘里手填 |

## 11. 自动同步（定时扫下载目录）

券商网页没有对外接口，系统不保存账号密码、也不调私有接口。可行的做法是：
**你在券商端导出一次（或交给第 12 节的自动下载），系统定时扫描下载目录并自动入库**。
华泰、东方财富、同花顺的导出文件都适用，不需要分别对接。

### 11.1 什么时候扫

交易日 09:35、11:35、13:05、15:05 各扫一次，对应开盘、午间休息、下午开盘、收盘。
配置了自动下载时，下载会在 09:33 / 11:33 / 13:03 / 15:03 先跑，落盘后立即触发一次扫描，不等定时点。
非交易日没有新文件就空跑，不会写任何数据。

### 11.2 扫描与去重

1. 只处理 `.xlsx` / `.csv` / `.txt`，且修改时间在最近 12 小时内（`max-age-minutes` 可改）。
2. 对文件**内容**取 SHA-256 作为指纹，写进 `t_sync_file`。同一份文件重复导出、改名，都不会再次入库。
3. 内容变了（例如午间导出比开盘多几笔）视为新文件重新解析；重复成交仍按「日期+代码+方向+价格+数量」逐行跳过，不会翻倍。
4. 类型识别：先看文件名里的「成交 / 资金 / 持仓」关键词，认不出再按三种类型各试解析一次，取必填列齐全且数据行最多的那种；都认不出就记 `SKIPPED`，**不猜着导**。
5. 问题行（合计行、备注行）不提交；失败原因写入 `t_sync_file.message`，可在页面上看到。

### 11.3 怎么判读「最近记录」

| 结果徽标 | 含义 | 动作 |
| --- | --- | --- |
| 已入库 | 有行写入，重复行被跳过 | 去记成交/账户页抽查首尾数据 |
| 已跳过 | 文件重复（指纹已存在）、认不出类型、缺必填列或没有数据行 | 换一份带标准表头的导出，或手动在下面导入 |
| 失败 | 所有行都校验失败 | 看「说明」列的行号与原因，修文件后重新导出（内容变化会重新处理） |

### 11.4 配置项（application.yml）

```yaml
trade-journal:
  sync:
    enabled: true
    directories:
      - ${SYNC_DIR:${user.home}/Downloads}
    account-id: 1
    default-reason: 自动同步
    max-age-minutes: 720
    max-files: 50
    recent-limit: 20
```

券商客户端的下载目录不是系统下载目录时，改 `directories`；用 `SYNC_DIR` 环境变量可以不改配置文件。
自动同步写入的成交理由统一是「自动同步」，在统计页「亏损原因分析」里能单独筛出来，后续可批量补写真实理由。

## 12. 自动下载（到点自己点导出）

第 11 节解决「不用手工上传」，这一节解决「不用手工下载」：到点用本机浏览器打开券商导出页，点导出，文件落盘后立即入库。

### 12.1 怎么工作

1. 交易日 **09:33、11:33、13:03、15:03**（比扫描早 2 分钟）依次执行配置里的券商任务。
2. 用 Playwright 启动本机 Chrome/Edge，**复用你手动登录后的 Cookie**，打开 `brokers[].url`。
3. 按 `brokers[].steps` 顺序点菜单、填条件、点导出；`download` 动作会等待文件真正下载完成。
4. 文件以 `yyyyMMdd-HHmmss-原文件名` 保存到下载目录，避免覆盖上一时段还没入库的导出。
5. 只要有文件落盘，立刻调一次自动同步（第 11 节）入库；单个券商失败只记 FAILED，不影响其它券商。

**不保存账号密码**：登录态是浏览器自己的 Cookie，存在 `user-data-dir` 里，和你本机 Chrome 的登录信息同等级。
**不猜页面**：选择器全部写在配置里，券商改版时改配置即可，不会因为改版把错误数据导进来。
**首次执行需要联网一次**：Playwright 驱动会在第一次运行时自动下载（约几十 MB）；配置了 `channel: msedge` 或 `chrome` 后直接用系统浏览器，不会再额外下载 Chromium。

### 12.2 首次使用

1. 登录券商网页，打开「成交/资金/持仓」查询页，按 F12 找到导出按钮的选择器（优先用稳定的 id）。
2. 在 `application.yml` 里填 `trade-journal.download.brokers`，步骤见 12.3。
3. 启动服务，打开「一键导入」页 →「自动下载」卡片 → 选券商 →「打开浏览器登录」，登录后关闭窗口。
4. 点「立即下载并导入」验证：落盘文件 ≥ 1 即打通；入库行数由文件内容决定。
5. 之后不用每天操作，定时任务会自己跑。

### 12.3 步骤怎么写

| action | 作用 | selector | value |
| --- | --- | --- | --- |
| `waitForSelector` | 等页面元素出现 | 元素选择器 | — |
| `click` | 点击（切菜单、打开导出弹窗） | 元素选择器 | — |
| `fill` | 输入（日期区间等） | 输入框选择器 | 要填的内容 |
| `press` | 按键（回车提交） | 输入框选择器 | `Enter` |
| `wait` | 固定等待，给页面渲染时间 | — | 毫秒数 |
| `download` | **点击并等待下载完成**，文件存入下载目录 | 导出按钮选择器 | — |

```yaml
trade-journal:
  download:
    enabled: true
    headless: true          # 定时任务无头；登录接口会强制有头
    channel: chrome         # chrome / msedge 用本机已装浏览器，不用 playwright install
    user-data-dir: ${user.home}/.trade-journal/browser
    timeout-seconds: 45
    # directories 为空时复用 sync.directories
    brokers:
      - name: 华泰
        url: https://trade.htsc.com.cn/xxx
        steps:
          - action: waitForSelector
            selector: "#menu-query"
          - action: click
            selector: "#menu-query"
          - action: click
            selector: "#export-button"
          - action: download
            selector: "#export-button"
```

上面的 URL 和选择器是**占位示例**，必须按你的实际页面替换；每家券商可以配多个任务，互不影响。

### 12.4 接口

| 动作 | 接口 | 说明 |
| --- | --- | --- |
| 状态 | `GET /downloads/status` | 券商列表、下载目录、定时点、上次每个券商的结果 |
| 立即下载 | `POST /downloads/run?broker=华泰` | 不传 `broker` 跑全部启用的任务 |
| 登录 | `POST /downloads/login?broker=华泰` | 打开有头浏览器，登录后关闭窗口即可 |

### 12.5 边界与排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Executable doesn't exist` | 本机没装 Chrome/Edge，或 `channel` 写错 | 装 Chrome/Edge，或把 `channel` 改成 `msedge` |
| 卡在 `waitForSelector` | 页面改版，或登录态过期被跳到登录页 | 重新登录；用 F12 更新选择器 |
| 显示「未触发下载」 | `steps` 里没有 `download` 动作 | 在导出按钮上补一个 `download` 步骤 |
| 下载了但没入库 | 表头认不出类型或缺必填列 | 看「自动同步」最近记录的说明，按第 11 节处理 |
| 浏览器启动失败/被占用 | 登录窗口没关，登录态目录被锁 | 关闭残留浏览器窗口后重试 |
| 非交易日也执行 | 定时规则是周一到周五，不判断节假日 | 没有新导出时脚本会跑空，不会写数据；节假日可在 `enabled` 关掉 |
