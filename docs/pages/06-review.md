# 06 每日复盘（tab-review）

> 页面位置：`static/index.html` → `<section id="tab-review">`；前端函数 `initReview`、`loadReviewHoldings`、`submitReview`、`loadReview`；后端 `ReviewController`、`ReviewService`、`DisciplineItem`。
> 数据链：成交建仓 → 本页填收盘价/现金/纪律 → `t_account_daily` 净值序列 → 统计页回撤、月度收益、纪律分布。

## 1. 这页回答什么（不回答什么）

回答：

- 今天账户总资产是多少，现金多少，持仓市值多少？
- 每只持仓今天收在哪、止损/止盈位是否还成立、买入逻辑有没有被破坏？
- 今天大盘发生了什么事实、哪些方向强/弱、错过了什么机会？
- 今天情绪如何、最重要的一条经验是什么、明天要做什么？
- 今天违反了哪几条纪律，本月最常犯的是哪一条？

不回答：

- 今天赚了多少已实现盈亏（去记成交页看 `realizedPnl`）。
- 胜率、盈亏比、最大回撤的最终数值（统计页从本页净值与流水推）。
- 持仓成本由谁决定（本页只读 `t_position`，不可改）。

## 2. 数据来源与查询条件

| 数据块 | 接口或表 | 过滤条件 | 何时刷新 |
| --- | --- | --- | --- |
| 当日文字 | `GET /reviews/{date}` → `t_daily_review` | 按主键 `review_date` 精确取一天 | 点「读取当日」 |
| 持仓收盘价表 | `GET /trades/positions` → `t_position` | 全局账户；选「全部账户」时不传 `accountId` | 进入页面、点「重新读取持仓」、切账户 |
| 提交复盘 | `POST /reviews` | 一次请求写 4 张表 | 点「提交复盘」 |
| 净值序列 | `t_account_daily`（统计页读取） | `account_id + trade_date`；全部账户按日期 `SUM(equity)` | 每次提交即 upsert |
| 持仓快照 | `t_position_daily` | `account_id + snapshot_date`，每标的一行 | 每次提交先删后写 |
| 纪律违背 | `t_discipline_violation` | 写入按 `review_date`；统计按 `review_date BETWEEN from AND to` | 每次提交先删后写 |

页面默认值：

- 日期默认今天（`initReview` 只在为空时填）。
- 现金、净值、7 块文字、持仓输入框**不会**因切换日期自动回填：`loadReview` 只恢复文字 7 项，并提示「违背需重新勾选」。
- 持仓表每行只有填了收盘价才会被提交；未填的行静默跳过。

## 3. 字段口径

| 字段 | 计算口径 | 来源 | 正常范围/参考 | 异常含义 |
| --- | --- | --- | --- | --- |
| 复盘日期 `reviewDate` | 主键，一天一条（不带账户） | 日期框 | 通常为今天 | 补录过去日期会覆盖当天旧记录 |
| 现金 `cash` | 必填，`>= 0` | 手工输入 | 与券商可用资金一致 | 漏填/多填直接扭曲净值；负数被拒 |
| 持仓市值 `marketValue` | `Σ(closePrice × position.quantity)` | 后端按 `t_position` 数量算 | >0（有持仓时） | 数量取数据库而非页面，页面显示可能滞后 |
| 净值 `equity` | 留空：`cash + marketValue`；填写则以填写值覆盖 | 后端 `ReviewService.save` | >0 | ≤0 报错；手填与自动值差异大说明现金或收盘价有误 |
| 仓位占比 `positionRatio` | `该标的市值 ÷ equity`，4 位四舍五入 | 后端写入快照 | 0~1 | 单只接近 1 表示满仓单票 |
| 收盘价 `closePrice` | 手填，正数；为空则不生成该行快照 | 页面输入 | 与行情收盘一致 | 用昨收/成本价代替会让净值曲线失真 |
| 数量 `quantity` | 直接取 `t_position.quantity` | `t_position` | ≥1（有持仓） | 与页面显示不同＝提交前刚录过成交 |
| 成本 `avgCost` | 直接取加权成本（含买入费用） | `t_position` | >0 | 仅展示，不能在本页修改 |
| 止损位 `stopLoss` | 可空，原样存快照 | 页面输入 | 可空 | 只存档，当前不参与统计/告警 |
| 止盈位 `takeProfit` | 可空，原样存快照 | 页面输入 | 可空 | 同上 |
| 逻辑成立 `logicValid` | 空按 `true`；页面默认勾选 | 页面复选框 | true 为主 | 连续 false 说明该仓已不该持有，却还没卖 |
| 大盘记录 `marketNote` | 自由文本，只写事实 | 页面 | 可空 | 写成判断会污染后续经验总结 |
| 强势/弱势方向 | 自由文本 | 页面 | 可空 | 与板块页对照时才可验证 |
| 错过机会 `missedOpportunity` | 自由文本 | 页面 | 可空 | 只记录「看到未做」及原因 |
| 情绪 `emotion` | 自由文本 | 页面 | 可空 | 多次违背常与情绪同日出现 |
| 经验 `lesson` | 自由文本，一天一条 | 页面 | 建议必写 | 空则该日复盘无沉淀 |
| 明日待办 `tomorrowTodo` | 自由文本 | 页面 | 可空 | 空则次日无执行清单 |
| 违背次数 `violationCount` | `violations.size()`，由后端回填 | 勾选项条数 | 0 最常见 | ≥2 时后端打 warn：多为行程或仓位超限 |
| 账户 `accountId` | 空按 1；影响快照与净值 | 全局账户 | 1、2… | 快照按账户隔离，文字/违背不隔离 |

纪律 7 项（`DisciplineItem`，代码与页面标签一一对应）：

| code | 标签 | 判定要点 |
| --- | --- | --- |
| `CHANGE_PLAN` | 盘中改计划 | 盘前写了触发条件，盘中临时改价/改仓位 |
| `OFF_PLAN` | 计划外交易 | 该笔在计划页找不到对应计划，或计划未触发 |
| `CHASE` | 追涨杀跌 | 在情绪驱动的高点买入/低点卖出 |
| `FOLLOW_TIP` | 听消息下单 | 下单依据是他人观点而非自己的规则 |
| `AVERAGE_DOWN` | 亏损加仓 | 逻辑已破坏仍向下摊薄成本 |
| `OVER_POSITION` | 超仓位上限 | 单票或总仓位超过自定上限 |
| `OVERTRADE` | 盯盘过频 | 无新信息却频繁查看或反复买卖 |

重复提交覆盖规则（同一天再提交一次＝修改）：

| 表 | 覆盖键 | 行为 |
| --- | --- | --- |
| `t_position_daily` | `account_id + snapshot_date` | 先删该账户当天全部快照，再按本次填了收盘价的标的重插 |
| `t_account_daily` | `account_id + trade_date` | `INSERT ... ON DUPLICATE KEY UPDATE`，改 equity/cash，不新增行 |
| `t_discipline_violation` | 仅 `review_date`（**不含账户**） | 先删当天全部违背，再按本次勾选重插 |
| `t_daily_review` | 仅 `review_date`（**不含账户**） | 存在则 update，`violationCount` 以本次勾选数为准 |

## 4. 分析步骤

记录顺序（收盘后按此顺序，不要跳步）：

1. 先回「记成交」把当天成交录完——复盘的数量取自 `t_position`，成交没录数量就是旧的。
2. 进入本页，确认右上角全局账户与日期。
3. 填「现金余额」，再逐行填持仓「收盘价」；止损/止盈有变化才改，「逻辑成立」逐只确认。
4. 净值留空（默认自动算）；只有券商结算价与现价差异大时才手填，并在经验里写明原因。
5. 写 7 块文字：先事实（大盘、强弱方向），再判断（错过机会、情绪），最后沉淀（经验、明日待办）。
6. 勾纪律：只勾今天真实发生的，没有就全不勾；不确定时按「最接近的行为」勾，不要多勾。
7. 提交，看 toast 的「违背 N 次」是否与勾选数一致。
8. 需要复核时点「读取当日」：文字能读回，现金/净值/收盘价/勾选需重填（避免误以为是系统丢数据）。

分析步骤（读历史时）：

1. 先看当日净值与现金，确认总资产口径（现金 + 持仓市值）。
2. 看仓位占比是否与自己的上限一致；只用页面表里填了收盘价的标的估算。
3. 逐只读「逻辑成立」：连续多日 false 而仓位未减，是纪律问题而非判断问题。
4. 对照当天成交：计划外交易是否与勾选的 `OFF_PLAN`/`CHASE` 对得上。
5. 读「情绪 + 经验 + 明日待办」三块，检查昨日待办是否在今天被执行。

## 5. 带数字的案例

> 以下为示例数据，非真实交易。

沿用 `05-trade.md` 的账户：期初现金 180000.00，11-05 买入 1000 股 @10.80（费 5.00），卖出 500 股 @11.20（费 5.00），剩余 500 股，`avgCost=10.8050`。

| 步骤 | 输入/操作 | 计算 | 结果 |
| --- | --- | --- | --- |
| ① 录成交后现金 | 手工填 `cash` | 180000 − 10805 + 5595 | 174790.00 |
| ② 填收盘价 | 500 股 @11.35 | 市值 500×11.35 | 5675.00 |
| ③ 净值留空 | 自动 | 174790.00 + 5675.00 | `equity=180465.00` |
| ④ 仓位占比 | 后端写快照 | 5675 ÷ 180465 | 0.0314（3.14%） |
| ⑤ 勾纪律 | 勾「追涨杀跌」「盯盘过频」 | 条数 | `violationCount=2`，触发 warn 日志 |
| ⑥ 次日 11-06 | 收盘 11.00，现金不变 | 市值 5500，净值 180290 | 回撤 (180465−180290)÷180465 = 0.10% |

覆盖与手填校验：

- 11-05 重新提交、收盘价改为 11.30：市值 5650，净值 180440；当天快照仍只有 1 行（先删后插），净值行被 upsert 覆盖。
- 同上但手填 `equity=180500`：净值序列记 180500，占比 5675÷180500=0.0314；此后回撤以 180500 为峰值基准。
- 若只提交买入留下的 1000 股而漏填卖出，数量仍是 1000、成本 10.8050，净值会被高估 5675 左右——数量永远以 `t_position` 为准，不以记忆为准。

## 6. 判读表

| 现象 | 结论 | 动作 |
| --- | --- | --- |
| 净值比昨日大幅跳变，现金没变 | 收盘价填错或漏填某只持仓 | 逐只核对收盘价，重新提交（覆盖不叠加） |
| 净值明显低于「现金 + 持仓成本」 | 浮亏，或某只持仓漏填收盘价被剔除 | 先补收盘价；再确认是否真浮亏 |
| 仓位占比合计 > 1 | 手填净值低于实际总资产 | 清空净值让系统自动算 |
| `violationCount ≥ 2` 且集中在同一天 | 多为行程冲突或仓位超出可执行范围 | 把纪律改成具体时间/动作，不要只靠自控 |
| `OVERTRADE` 连续多日出现 | 交易频率超出策略需要 | 降低看盘频率，设固定决策时点 |
| 多只持仓连续 `logicValid=false` 却未减仓 | 决策已失效但执行滞后 | 次日待办写明减仓条件与时限 |
| 「读取当日」后净值/勾选为空 | 接口只返回文字与次数，不回填表单 | 正常，重填后覆盖提交 |
| 同日切账户提交后，另一账户的违背消失 | 违背与文字按日期覆盖，不按账户隔离 | 纪律按「人」记，当天只提交一次 |
| 统计页月度收益首月标记 `partial` | 该月没有上月净值基数，用当月首个净值起算 | 正常，不与完整月份直接比较 |

## 7. 数据前提与常见问题

- **现金必填**：前端拦截空值，后端 `@NotNull`；填 0 允许，但会让占比与净值严重失真。
- **净值自动算依赖收盘价**：只填部分持仓时，未填的标的市值按 0 计，净值被低估，回撤被放大。
- **数量取数据库**：提交瞬间以 `t_position` 为准；复盘后补录成交不会自动修正已写快照，需重新提交。
- **快照按账户、文字按日期**：`t_position_daily`/`t_account_daily` 按 `account_id+日期`；`t_daily_review`/`t_discipline_violation` 只按日期，切账户提交同一天会覆盖文字与违背。
- **纪律统计不按账户过滤**：统计页的月度违背是「人」的口径，与当前账户无关。
- **止损/止盈/逻辑成立只存档**：目前没有页面读取这三列做告警或统计，不能指望系统提示破位。
- **没有删除接口**：撤销某天复盘只能改库；重复提交只能覆盖，不能清空为「无记录」。
- **日期不限制未来**：选未来日期也能保存，会让净值序列出现未来点，回撤与月度收益口径被拉长。
- **空持仓可提交**：持仓数组为空时市值 0，净值＝现金；清仓日应这样提交，仓位占比不生成。
- **`positionRatio` 保留 4 位**：0.0314 表示 3.14%，不要按 31.4% 读。

## 8. 联动

- **回撤**：统计页从 `t_account_daily` 按日期取净值，维护历史峰值算 `(峰值−当前)/峰值`；少于 2 个净值点不给回撤。
- **月度收益**：月末净值 ÷ 上月末净值 − 1；每月只取该月首个与最后一个净值点，中间漏提交不影响首末，但会漏掉路径波动。
- **纪律分布**：统计页按月、按 `item_code` 计数，本页每勾一项就多一条明细；`violationCount` 与明细条数始终一致。
- **标的分析**：收盘价快照是标的价格曲线的唯一来源（`t_position_daily`），没提交复盘就没有该日点位。
- **账户页**：总权益、现金、持仓市值、浮动盈亏全部取最近一条 `t_account_daily` 与快照，不复用 `t_position`。
- **成交页**：本页持仓行来自成交维护的 `t_position`；成交漏录，本页就少一行，净值随之少一块。
- **统计口径选择**：全局账户为「全部账户」时净值按日期求和，单账户时取该账户；纪律违背在任何账户下都是全量。
