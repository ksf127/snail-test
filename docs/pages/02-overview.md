# 统计总览（导航「统计」/ 页面标题「账户总览」，tab-overview）

> 代码位置：`static/index.html` 的 `tab-overview`、`loadOverview / renderKpis / renderPnl / renderReasons /
> renderEquity / renderMonthly / renderPlanCompare / renderSector / renderDiscipline / tradeRow`；
> 后端 `StatService`、`StatMapper`、`SectorRefService`。

## 1. 这页回答什么（不回答什么）

**回答**

- 这个区间、这个账户（或全部账户）到底赚没赚：区间收益、最大回撤、净值曲线。
- 钱是怎么赚的、怎么亏的：盈利/亏损金额、笔数、平均每笔、盈亏比、最大单笔。
- 计划内和计划外差多少：胜率、盈亏比、累计盈亏。
- 亏损集中在哪些卖出理由、哪些标的；哪个月最差；纪律违背集中在哪一项。
- 持仓跑赢还是跑输中证银行。

**不回答**

- 不回答账户现金余额、单账户明细——去「账户与资金」。
- 不回答单只标的完整买卖点——去「标的分析」；也不做实时行情、不做汇率换算，板块只是参考基准。

## 2. 数据来源与查询条件

**统一口径**：本页所有卡片共用顶部 `from/to` + 全局账户下拉框。进入页面默认 `from = 今天−29 天`、`to = 今天`；点「近 7 天 / 近 30 天 / 本月 / 今年 / 全部」会先改日期再立即拉取。表格内筛选只影响该表：成交明细带自身条件重新请求 `/trades`（仍锁定同一 `from/to` + 全局账户），板块表的涨跌/每页是纯前端过滤；都不会回写顶部条件，也不改变上方卡片。

| 数据块 | 接口或表 | 过滤条件 | 何时刷新 |
| --- | --- | --- | --- |
| 8 个 KPI | `/stats/overview` + `/stats/equity` + `/stats/performance` | `t_trade` 取 `side='SELL' AND realized_pnl IS NOT NULL`；`t_account_daily` 按日 SUM；纪律违背除外（见下） | 点「拉取统计」、日期快捷键、切换全局账户 |
| 收益与亏损结构 | `/stats/performance` → `t_trade` | 区间 + `side='SELL'`；净额把 `realized_pnl` 为空的卖出按 0 计 | 同上 |
| 亏损原因 | `/stats/reasons?limit=8` → `t_trade` | 区间 + `side='SELL' AND realized_pnl IS NOT NULL`；`TRIM(reason)` 为空归为「未记录原因」；按卖出笔数降序取前 8 | 同上 |
| 亏损标的 Top | `/stats/symbols` → 成交 + 持仓快照 | 同一 `from/to` + 账户；前端只取 `realizedPnl < 0`，按亏损额升序取前 5 | 同上 |
| 净值曲线 | `/stats/equity` + `/stats/symbols.series` | `t_account_daily` 区间按日 SUM；标的价格取 `t_position_daily` 区间快照 | 同上 |
| 月度收益 | `/stats/monthly` → `t_account_daily` + `t_trade` + `t_discipline_violation` | 净值/成交按区间 + 账户；违背次数**不按账户** | 同上 |
| 成交明细 | `GET /trades` → `t_trade` | 区间 + 账户 + 关键字/方向/来源/盈亏/排序/分页 | 拉取统计后；筛选、翻页、重置 |
| 计划内 / 计划外 | `/stats/overview.trades` → `t_trade` | 区间 + 账户 + `side='SELL' AND realized_pnl IS NOT NULL`，按 `is_planned` 分组 | 拉取统计 |
| 板块参考 | `/refs/sectors?sector=399986` → `t_sector_daily` | 区间 + `sector_code='399986'`；**不带账户参数** | 拉取统计；表内筛选/翻页 |
| 按月纪律 | `/stats/overview.discipline` → `t_discipline_violation` | `review_date` 落在区间；**刻意不按账户过滤** | 拉取统计 |

## 3. 字段口径

### 3.1 顶部 8 个 KPI

| 字段 | 计算口径 | 来源 | 正常范围/参考 | 异常含义 |
| --- | --- | --- | --- | --- |
| 区间收益 | `(最后一个净值 / 第一个净值 − 1) × 100`，百分数本身，2 位小数 | `/stats/equity`，按日 SUM 后的首尾点 | 可正可负；副标题显示「N 个净值点」，0 点显示「暂无净值数据」 | 点数 < 2 或首点 ≤ 0 → 「—」，不是 0% |
| 已实现净收益 | 区间内所有卖出 `realized_pnl` 之和；`realized_pnl` 为空的卖出按 0 计入 | `/stats/performance.netRealized` | 可正可负；副标题「N 笔卖出 · 胜率 x%」 | `net=0 且 sellCount=0` 才显示「—」；有卖出但净额为 0 显示 0.00 |
| 已实现盈利 / 亏损 | 盈利合计 = 所有 `realized_pnl>0` 的卖出相加；亏损合计 = 所有 `realized_pnl<0` 的卖出求和后**取绝对值** | `/stats/performance.profitAmount / lossAmount` | 两者均 ≥ 0，分列「+ / −」 | 亏损合计永远是正数展示，别再加负号 |
| 最大回撤 | 扫描区间净值，维护历史峰值，`(峰值 − 当前) / 峰值` 的最大值；后端存 0~1，页面乘 100 保留 2 位 | `/stats/overview.drawdown` | 0~100%；副标题「峰值日 → 谷底日」 | 点数 < 2 时后端返回 `0` 且日期为空，页面是「0.00% + 净值点不足」，不是真的零回撤 |
| 计划内胜率 | `winTrades / closedTrades`，后端 0~1，页面乘 100 保留 1 位 | `/stats/overview.trades` 中 `isPlanned=true` | 0~100%；副标题「N 笔平仓 · 盈亏比 x」 | 该组无记录 → 「—」，不是 0% |
| 计划外胜率 | 同上，`isPlanned=false` | 同上 | 0~100% | 同上；计划外常与计划内直接比较 |
| 已实现盈亏比 | `avgWin / abs(avgLoss)`，2 位小数 | `/stats/performance.profitFactor` | >1 赚一次能覆盖一次亏；<1 需要更高胜率 | 无盈利、无亏损或 `avgLoss=0` → 「—」，不是 999 |
| 纪律违背 | 区间内所有月份 `total` 之和；每个违背明细计 1 次 | `/stats/overview.totalViolations` | ≥ 0；副标题「N 个月有记录」 | **不随全局账户变化**；月份数不等于违背次数 |

### 3.2 收益与亏损结构

| 字段 | 计算口径 | 来源 | 正常范围/参考 | 异常含义 |
| --- | --- | --- | --- | --- |
| 环形图「盈利金额」 | `profitAmount`，只加正收益卖出 | `/stats/performance` | ≥ 0 | 与「亏损金额」同时为 0 时没有结构可看 |
| 环形图「亏损金额」 | `lossAmount`，负收益求和后取绝对值 | 同上 | ≥ 0 | 图上显示为正数，但代表亏损 |
| 环心「净」 | `netRealized`，盈利 − 亏损 | 同上 | 可正可负 | — |
| 盈利笔数 / 亏损笔数 | `realized_pnl>0` / `<0` 的卖出笔数 | 同上 | ≥ 0 | 两者之和可能小于卖出笔数：`realized_pnl=0` 的卖出既不赢也不亏 |
| 胜率 | `winCount / sellCount`，后端 0~1，页面乘 100 保留 1 位 | 同上 | 0~100% | `sellCount=0` → 「—」；分母含 0 盈亏的卖出 |
| 盈利合计 / 亏损合计 | 同环形图两项，分别带 `+ / −` | 同上 | ≥ 0 | 亏损合计展示为 `-绝对值` |
| 平均盈利 / 平均亏损 | `avgWin = 正收益合计 / 盈利笔数`；`avgLoss = 负收益合计 / 亏损笔数`，后端为负数，页面取绝对值展示 | 同上 | 金额 | 无盈利样本时平均盈利显示「+—」；无亏损样本时平均亏损按 0 显示「-0.00」 |
| 盈亏比 | `avgWin / abs(avgLoss)`，2 位 | 同上 | >1 较健康；<1 需高胜率补偿 | 无亏损样本 → 「—」 |
| 最大单笔盈利 / 亏损 | `maxWin` / `maxLoss`（后端 `maxLoss` 为负数，页面取绝对值） | 同上 | 金额 | 单笔极值决定尾部风险，需与平均亏损对照；无样本时分别显示「+—」「-0.00」 |
| 平均每笔 | `netRealized / sellCount`；`sellCount=0` 显示「—」 | 图表右上 meta | 可正可负 | 分母是卖出笔数，不是全部成交笔数（含买入） |

### 3.3 亏损原因与亏损标的 Top

| 字段 | 计算口径 | 来源 | 正常范围/参考 | 异常含义 |
| --- | --- | --- | --- | --- |
| 卖出理由 | `COALESCE(NULLIF(TRIM(reason),''),'未记录原因')` 分组；返回条数上限 8 | `/stats/reasons` | 最多 8 类；顶部「共 N 类」是返回数，不是全部类别数 | 类别多于 8 时，表中卖出笔数之和 < 区间总卖出 |
| 卖出笔数 | 该理由下 `side='SELL' AND realized_pnl IS NOT NULL` 的笔数 | 同上 | ≥ 1 | — |
| 盈利 / 亏损（列） | 该理由下 `realized_pnl>0` / `<0` 的笔数 | 同上 | ≥ 0 | 两者相加可小于卖出笔数（0 盈亏） |
| 胜率 | `winCount / sellCount`，后端 0~1，页面乘 100 保留 1 位 | 同上 | 0~100% | 「—」只在 `sellCount=0`，实际按组过滤后不会出现 |
| 已实现盈亏 | 该理由下 `realized_pnl` 求和，2 位 | 同上 | 可正可负；负数标红 | 与亏损标的 Top 是两种维度，不可逐项相加对平 |
| 平均每笔 | 该理由下 `AVG(realized_pnl)`，2 位 | 同上 | 可正可负 | — |
| 亏损标的「标的」 | `symbol` + `name`，来自区间标的统计 | `/stats/symbols` | 前 5 只 | 只含**已实现**亏损，不含浮亏 |
| 亏损标的「已实现盈亏」 | 该标的区间卖出 `realized_pnl` 之和，负数 | 同上 | 负值 | 与标的分析页同源，可交叉核对 |
| 亏损标的「卖出笔数」 | `sellCount` | 同上 | ≥ 0 | — |
| 亏损标的「区间涨跌」 | `(最后一个收盘价 − 第一个收盘价) / 第一个收盘价 × 100`，百分数本身，2 位 | `t_position_daily` 快照 | 可正可负 | 首价为 0 → null；没有快照 → 空，不用买入价补点 |
| 操作「看走势」 | 跳标的分析并选中该代码 | 前端 `data-jump-symbol` | — | 理由文本本身不可点 |

### 3.4 账户净值曲线

| 字段 | 计算口径 | 来源 | 正常范围/参考 | 异常含义 |
| --- | --- | --- | --- | --- |
| 曲线归一化 | 每条线以自身区间第一个值归一化为 100；首点 ≤ 0 时退化为原始值；虚线 100 只画在第一条序列上 | `indexLineChart` | 100 为起点 | 归一化后只能比形态，不能比金额；线在 100 上方=区间上涨 |
| 账户净值线 | 每日 `SUM(equity)`，原始值放悬停提示 | `/stats/equity` | ≥ 0 | 点数 < 2 → 曲线为空 |
| 标的线 | 区间内有快照的每只标的 `close_price`，过滤掉空值；无点的标的不画 | `/stats/symbols.series` | — | 没有复盘快照就没有标的线 |
| 图例涨跌 | 序列末值 / 首值 − 1，显示 2 位百分数 | 前端 legend formatter | 可正可负 | 与图例前 100 基准对应 |
| 顶部 meta | 起始净值、最新净值、区间收益（同 KPI 公式） | `/stats/equity` | — | 无净值时整行清空；空态提示去每日复盘 |

## 4. 分析步骤

1. 先确认顶部「起始日期 / 结束日期」和全局账户；默认近 30 天。改完点「拉取统计」，或直接点日期快捷键（会自动拉取）。
2. 从左到右读 8 个 KPI：**区间收益 → 最大回撤 → 计划内胜率 → 计划外胜率 → 盈亏比 → 纪律违背**；同时看每个副标题的样本量，样本太小先别下结论。
3. 点 KPI「已实现净收益」或滚到「收益与亏损结构」，看盈利/亏损金额、笔数、平均盈利/亏损、最大单笔；确认是「少数大赚」还是「很多小亏」。
4. 滚到「亏损原因分析」：按卖出笔数从多到少看，找「笔数多 + 胜率低 + 已实现负」的理由；再到「亏损标的 Top」点代码，跳到标的分析看买卖节奏。
5. 看「账户净值曲线」：悬停找峰值日和谷底日，与 KPI 最大回撤对照；再比较账户线与标的线的相对强弱。
6. 看「月度收益」：找最差月份和环比最负的月份，把该月成交笔数、违背次数放在一起读；首月带「部分」不要横比。
7. 在「成交明细」筛选：方向=卖出、来源=计划外、盈亏=亏损、排序=盈亏倒序，逐笔看理由；看完点「重置」。
8. 最后读「计划内 / 计划外对比」确认差距，读「板块参考」判断是不是方向问题，读「按月纪律违背」找当月第一项。

## 5. 带数字的案例

> **以下为示例数据。** 区间 2026-09-01 ~ 2026-10-31，全局账户=全部账户。

- 净值与回撤：起点 500,000.00，9 月末 509,000.00（月 +1.8%），10 月末 484,059.00（月 −4.9%），区间收益 −3.2%；峰值 520,000.00（2026-09-18）→ 谷底 476,320.00（2026-10-16），最大回撤 8.4%。
- 卖出：14 笔，6 胜 8 负，胜率 42.9%；盈利合计 +10,450.00，亏损合计 12,300.00，净已实现 −1,850.00；平均盈利 1,741.67，平均亏损 1,537.50，盈亏比 1.13；最大单笔亏损 −4,200.00。
- 计划内：9 笔平仓，5 胜，胜率 55.6%，累计 +2,050.00；计划外：5 笔平仓，1 胜，胜率 20.0%，累计 −3,900.00。
- 亏损原因「追高」：6 笔卖出，1 胜 5 负，已实现 −4,200.00，平均每笔 −700.00。
- 10 月环比 −6.7 pp；同比无去年数据，显示「—」。

**判断链**

1. **现象**：区间只亏 3.2%，但最大回撤 8.4%；计划内胜率 55.6%，计划外只有 20.0%；亏损原因第一名「追高」6 笔亏 4,200.00；10 月单月 −4.9%，环比 −6.7 pp。
2. **结论**：计划内是正期望，亏损主要来自计划外追高；10 月是主要亏损月；8.4% 的回撤远大于 3.2% 的区间亏损，说明中途有过深坑，仓位或止损有问题。
3. **该点哪里**：点 KPI「计划外胜率」→ 看「计划内 / 计划外对比」；点 KPI「已实现盈利 / 亏损」→ 看「亏损原因分析」的「追高」行和「亏损标的 Top」；滚到「月度收益」看 10 月行，再回「账户净值曲线」悬停 2026-09-18 与 2026-10-16。
4. **该改什么**：把「追高」加入禁做清单，计划外交易必须先写计划再下单；10 月回撤段主动降仓；把止损执行纳入每日复盘纪律；下个区间复核计划内外胜率差是否收窄、最大回撤是否降到区间亏损附近。

## 6. 判读表

| 现象 | 结论 | 动作 |
| --- | --- | --- |
| 区间收益为负，但计划内胜率明显高 | 亏损由计划外或少数大亏贡献 | 看计划对比的累计盈亏；成交明细筛「计划外 + 亏损」逐笔看理由 |
| 最大回撤远大于区间亏损（如 8.4% vs −3.2%） | 中途深坑后收回，仓位/止损有漏洞 | 看净值曲线峰值→谷底区间；复盘该段持仓与止损执行 |
| 计划外胜率比计划内低 20 pp 以上 | 临时起意是负期望 | 计划外交易强制写计划；把高频亏损理由加入禁做清单 |
| 盈亏比 >1 但胜率 <40% | 靠少数大赚覆盖多数小亏，连亏承受力是关键 | 看最大单笔亏损、最大回撤；控制单笔风险与连亏后的仓位 |
| 某一类理由笔数多、胜率低、已实现为负 | 决策模板有问题，不是运气 | 针对该理由改规则；下期只观察该类是否减少 |
| 亏损标的 Top 的区间涨跌为正 | 标的没选错，卖点/追高造成亏损 | 点代码去标的分析，核对买入价与卖出日 |
| 某月收益大负、环比大幅负 | 单月风险集中 | 看该月成交笔数与违背次数；回看当月复盘 |
| 某月纪律违背的第一项占比 ≥50% | 单一习惯是主要问题 | 下月只盯这一项；复盘时逐日勾选验证 |

## 7. 数据前提与常见问题

- **共用条件**：所有卡片都吃顶部 `from/to` + 全局账户；例外只有纪律违背（不分账户）和板块行情（不涉及账户）。表格内筛选只影响本表，不改卡片。
- **净值点不足**：区间只有 1 个净值点时，区间收益显示「—」；最大回撤显示「0.00% + 净值点不足」（后端返回 0 而非 null），不要读成「没有回撤」。净值单调上涨时回撤也是 0.00%，副标题会显示首日 → 首日。
- **默认区间**：首次进入是「今天−29 天 ~ 今天」共 30 天；「全部」是 2000-01-01 至今。日期改完必须点「拉取统计」，只有快捷键会自动拉取。
- **全局账户 / 停用账户**：切账户会整页重载；「全部账户」会把各账户成交合并、净值按日 SUM，并可能包含已停用账户的历史，而账户页只展示启用账户。对不上时先查账户是否停用。
- **纪律违背**：永远不按账户过滤，且每个明细行计 1 次，不是违背天数；同一天可能有多条。
- **亏损原因只取前 8 类**：类别多时表中卖出笔数之和小于总卖出；`realized_pnl=0` 的卖出计入卖出笔数，但既不算盈利也不算亏损，所以「盈利 + 亏损」可能小于卖出笔数。
- **金额符号**：`lossAmount`、`avgLoss`、`maxLoss` 在后端为负数或取绝对值，页面统一展示为 `-绝对值`；不要再手动加负号。`netRealized` 可正可负。
- **样本口径**：成交明细的「成交额」= 价格 × 数量，不含费用；标的统计的 `buyAmount` 含费用，二者不能直接对平。平均每笔 = 净已实现 / 卖出笔数，不是 / 全部成交笔数。
- **月度口径**：首月用当月第一个净值作基数并标「部分」；环比/同比是 pp，缺失显示「—」不是 0；成交笔数含买入，违背次数与成交无关。
- **跨页对不上**：账户页「已实现盈亏」是全部历史且全部启用账户；本页是区间且按所选账户。先把日期调到「全部」、账户调到「全部账户」，再看是否一致。
