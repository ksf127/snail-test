# 03 标的分析

> 页签 `index.html#tab-symbols`；接口 `GET /stats/symbols`、`GET /stats/equity`；涉及表 `t_trade`、`t_position_daily`、`t_position`、`t_account_daily`。

## 1. 这页回答什么（不回答什么）

回答（限所选区间、所选账户）：

- 钱是哪几只票赚的、哪几只拖累的，已实现盈亏各是多少、合计多少；
- 每只票成交几笔、卖出几笔、卖出胜率多少、买入额与卖出额多少；
- 标的本身的价格涨跌与你的已实现结果差多少，用来区分「选股错了」还是「卖点错了」；
- 哪些票还持有、哪些已经清仓。

不回答：

- **不回答浮动盈亏**：页面只有已实现口径，持仓的成本与现价差要看账户页的持仓市值/浮盈；
- **不回答实时行情与买卖点位置**：曲线是每日复盘写入的收盘价，图上没有成交标记；
- 不回答计划归因（计划内/外胜率在统计总览）；
- 不统计区间外的卖出，也不把区间外买入计入买入额（但成本会通过持仓带入）；
- 不回答账户整体收益与回撤（统计总览、账户页负责）。

## 2. 数据来源与查询条件

| 数据块 | 接口或表 | 过滤条件 | 何时刷新 |
| --- | --- | --- | --- |
| 标的汇总与明细行 | `GET /stats/symbols?from=&to=[&accountId=]`，聚合 `t_trade` | `trade_date BETWEEN from AND to`；`accountId` 为空=全部账户（同一代码跨账户合并一行）；`GROUP BY symbol`；`ORDER BY realizedPnl DESC, symbol` | 首次进入页签；点「拉取标的统计」；点近 7 天/近 30 天/本月/全部；录成交、批量导入、上传导入、提交复盘后 `loaded.symbols=false`，下次进页签重取 |
| 收盘价快照 | 同接口内的 `t_position_daily` | `snapshot_date BETWEEN from AND to` + `accountId`；按 `symbol, snapshot_date` 升序 | 与上一行同一次加载 |
| 当前持仓数量 | 同接口内的 `t_position` | 只按 `accountId` 汇总 `quantity`，**不带日期条件** | 与上一行同一次加载 |
| 账户净值（走势灰线） | `GET /stats/equity` ← `t_account_daily` | `trade_date` 区间；全部账户按日期 `SUM(equity)` | 与标的同一次加载 |
| 标的盈亏贡献图 | 前端 `contribBarChart(rows,total)`，不发额外请求 | 使用标的接口全量 `rows`，**不受明细筛选影响** | 随标的接口 |
| 表格筛选/排序/分页 | 前端本地 `symFiltered()` | 见 §3；不改变接口参数 | 点「筛选」、改「盈亏/持仓/排序/每页」下拉、回车、点分页 |

日期默认值：进页面填「今天−29 天」~「今天」。快捷区间：近 7 天=今天−6、近 30 天=今天−29、本月=当月 1 号、全部=2000-01-01~今天。`from`/`to` 为空或 `from > to` 时只提示、不发请求。

## 3. 字段口径

**标的来源**：取「区间内有成交（`t_trade`）+ 区间内有持仓快照（`t_position_daily`）+ 当前仍持仓（`t_position`）」三处并集。只取成交会漏掉「买了但一直没卖」的票，只取持仓会漏掉「区间内已清仓」的票。实现提示：当前持仓这一路只用于补 `holdingQuantity`；若某标的既无区间成交也无区间快照，接口当前不会为其新建一行（以接口返回为准）。

| 字段 | 计算口径 | 来源 | 正常范围/参考 | 异常含义 |
| --- | --- | --- | --- | --- |
| 代码 | 原样输出 `symbol` | `t_trade.symbol` / `t_position_daily.symbol` | 6 位数字常见 | 带后缀或空格会与其他页代码对不上 |
| 名称 | 成交路取 `MAX(name)`；仅快照路取该标的第一条快照 `name` | `t_trade.name` / `t_position_daily.name` | 与代码一致 | 改名后同代码两个名称时取成交中的 MAX |
| 成交笔数 | 区间内 `COUNT(*)`，买+卖都算 | `t_trade` | ≥1 | 为 0 一般说明该行只来自快照/持仓 |
| 卖出笔数 | `side='SELL'` 的计数 | `t_trade` | ≤成交笔数 | 等于成交笔数=区间内只卖未买（区间前建仓） |
| 胜率 | `winCount / sellCount`；`winCount = side='SELL' AND realized_pnl > 0`；前端 ×100 保留 1 位 | 计算值 | 40%~60% 常见；<35% 偏差 | 「—」=卖出 0 笔；盈亏恰为 0 的卖出不算赢也不算输 |
| 买入额 | `Σ(price × quantity + fee)`，**含买入费用**，2 位小数 | `t_trade` 的 BUY | 与卖出额同量级 | 远小于卖出额：区间前已建仓 |
| 卖出额 | `Σ(price × quantity − fee)`，**已扣卖出费用** | `t_trade` 的 SELL | — | 为 0：区间内只买未卖 |
| 已实现盈亏 | `Σ COALESCE(realized_pnl,0)`；单笔=`卖出金额−卖出费用−加权成本×数量`，成本含买入费 | `t_trade.realized_pnl` | 与账户合计同号看总量 | 与区间涨跌反号=操作与价格背离 |
| 区间涨跌 | `末快照收盘价 / 首快照收盘价 − 1`，×100 保留 2 位；首价为 0 时返回 null | `t_position_daily.close_price` | -20%~+20% 常见 | 「—」=区间内无快照；**只反映价格，与买卖时点无关** |
| 当前持仓 | `t_position.quantity` 按 `accountId` 求和，是**查询时刻**的持仓 | `t_position` | ≥0 | 0 显示「已清仓」；可能与区间末持仓不同 |
| 贡献图·已实现盈亏柱 | 每行 `realizedPnl`；≥0 绿、<0 红，标签带正负号 | 前端 | — | 柱方向即盈亏方向 |
| 贡献图·账户合计虚线 | 前端 `Σ realizedPnl`，`markLine xAxis=total` | 前端 reduce | 与统计页「净已实现」同口径 | 合计为正但多数柱向左=少数票赚、多数票亏 |
| 贡献图·区间涨跌柱 | 走顶部第二轴（%），null 不画 | `priceChangePct` | 与左轴金额不可直接比大小 | 金额与百分比方向相反=节奏问题 |
| 走势·标的线 | 该标的收盘价序列，只含有复盘的日子，缺口不补点 | `t_position_daily` | — | 点少/线断=期间没做复盘 |
| 走势·账户整体线 | 区间账户净值，按日 `SUM` | `t_account_daily.equity` | — | 两线起点不同日时不能直接比斜率 |
| 走势·归一化与图例 % | 每条线以**各自第一个点**=100；图例 `%=(末点/首点−1)×100` | 前端 `indexLineChart` | 100 为基线 | 图例 % 与列「区间涨跌」应接近；差大=两者日期范围不一致 |
| 走势 meta 首/末 | 接口 `firstClose`、`lastClose` | `/stats/symbols` | — | 显示「—」=无快照 |
| 标的数/账户合计 | `sym-contrib-meta`：未经筛选的行数；已实现合计 | 前端 | — | 与明细「共 N 只」不一致是正常的（后者是筛选后） |

本地筛选与排序：代码/名称 contains（忽略大小写）；盈亏 WIN=`realizedPnl>0`、LOSS=`<0`（0 两边都不进）；持仓 YES=`holdingQuantity>0`、NO=`≤0`；排序默认「已实现盈亏倒序」，另有升序/区间涨跌/成交笔数/代码；每页 10/20/50（默认 10）。

## 4. 分析步骤

1. 「区间筛选」填起始/结束日期，或点「近 7 天」「近 30 天」「本月」「全部」，再点「拉取标的统计」。
2. 看「标的盈亏贡献」右上 meta：标的 N 只、账户合计 X；扫横柱判断盈亏是集中在 1~2 只还是分散；柱越过灰色虚线即贡献超过平均合计。
3. 看橙色柱（顶部 % 轴），把「金额为负、百分比为正」的票标出来，这是本页最值得追的一组。
4. 在「单标的明细」保持排序=已实现盈亏倒序，记下前 3 与后 3；再切升序确认最大亏损票。
5. 点该行任意单元格，「单标的走势」切换；先读 meta 的首/末/区间/已实现，再比较图例里标的 % 与「账户整体」%。
6. 「盈亏」选亏损 +「持仓」选仍有持仓，得到「套着没卖」清单，逐只点开看是否已跌破逻辑。
7. 「持仓」选已清仓，核对卖出是否发生在上涨段中途；必要时回「记成交」看该票流水。
8. 复制代码去「统计总览 → 亏损原因分析」按卖出理由核对；结束点「重置」恢复默认筛选。

## 5. 带数字的案例

以下为示例数据（区间 2026-09-01 ~ 2026-10-31，代码 600000）：

- 快照首 18.00、末 19.22 → 区间 **+6.78%**；账户整体归一化 100 → 102.10（**+2.10%**）；
- 成交 5 笔（2 买 3 卖）；买入额 18,210.00、卖出额 17,790.00、已实现 **−420.00**；
- 两次买入：600 股@18.00 费 5.00、400 股@18.50 费 5.00 → 加权成本 18.21；
- 三笔卖出：+202.00（10-16，300 股@18.90，费 5.00）、−83.00（10-24，300 股@17.95，费 5.00）、−539.00（10-29，400 股@16.90，费 15.00）；
- 卖出 3 笔、盈利 1 笔 → 胜率 **33.3%**；当前持仓 0（已清仓）；平均亏损 −311.00，盈亏比 0.65。

**现象**：价格 +6.78%，账户 +2.10%，标的跑赢账户 4.68 个百分点；但已实现 −420.00，胜率仅 33.3%；亏损高度集中在最后一笔（−539.00 占亏损额 86.7%）。

**结论**：不是选股问题，是卖出节奏问题——先小赚跑、亏损单扛到被迫割；胜率低且平均盈利（+202.00）小于平均亏损（311.00），盈亏比 0.65，结构上不可持续。

**动作**：① 点开走势确认 10-29 是否卖在阶段低点；② 去统计总览查该票卖出理由是否集中在「怕回撤/没止损」；③ 下一轮把卖出条件写成「价格+时间」的可判定规则（如「跌破 18.60，或 10:30 前未站上 19.30 减半」）并落进盘前计划；④ 30 天后复核该票胜率是否回到 50%、盈亏比是否 >1。

## 6. 判读表

| 现象 | 结论 | 动作 |
| --- | --- | --- |
| 区间涨跌为正、已实现为负 | 选股对、卖点错（拿不住） | 点开走势核对卖点；把卖出条件规则化 |
| 区间涨跌为负、已实现为正 | 靠波段或低成本赢过标的 | 保留节奏，但样本 <5 笔时先别归因为能力 |
| 前 2 只贡献 >70% 合计 | 收益集中，复制性存疑 | 查这 2 只的计划内/外标记；其余票降为观察仓 |
| 多数票小亏、1 只大亏 | 止损不统一 | 按已实现升序取最大亏损票，查理由与止损执行 |
| 胜率 >50% 但已实现为负 | 小赚多次、大亏一次 | 先砍单笔最大亏损，再谈提高胜率 |
| 买入额 ≫ 卖出额且持仓 >0 | 区间内只加不减 | 持仓筛 YES，确认逻辑是否仍成立 |
| 卖出额 ≫ 买入额、已清仓 | 区间前建仓、区间内清仓 | 成本由持仓带入，别把买入额小误读成没买 |
| 区间涨跌「—」但已实现有数 | 期间没有复盘快照 | 补每日复盘；不要用成交价反推涨跌 |
| 成交笔数高、金额小、反复同价 | 区间内来回挨打 | 降频，放宽止损止盈，先停手一周 |

## 7. 数据前提与常见问题

- 快照只在「每日复盘」提交时写入。没有复盘就没有收盘价：区间涨跌为「—」，走势出现断点，图例 % 也会缺失。
- 收盘价是手工录入且未复权，除权日会出现跳空，涨跌幅会被算成真实下跌。
- 已实现盈亏只统计区间内卖出的记录；区间外卖出不计入，区间外买入只通过持仓成本影响结果，因此「买入额」可能小于「卖出额」。
- 全部是已实现口径，不含浮盈浮亏；持仓 >0 的票在表里看不到未实现结果。
- 当前持仓是查询时刻的 `t_position`，不是区间末持仓；区间内卖了又买会同时体现买卖笔数。
- 全部账户视图会把同一代码跨账户合并成一行；单账户视图只显示该账户的快照，两者走势长度可能不同。
- 盈亏恰为 0 的卖出既不计入胜率分子也不计入分母，胜率可能因此低于直觉。
- 贡献图与明细表用同一份数据：图不受本地筛选影响，明细会随筛选变化；「账户合计」是这些票的已实现之和，不是账户净值收益。
- 走势图两条线各自以自己的第一个点为 100。起点日期不同时只能比较到区间末的图例 %，不能比斜率。
- 标的来源含当前持仓，但接口实现只给已有成交/快照的标的补数量；持仓里多出来的票以接口返回为准。

## 8. 联动

- 点明细任意行 → 上方「单标的走势」切换（`selectSymbol`），同时高亮该行。
- 「记成交」「当前持仓」「统计总览」的亏损 Top/成交明细，以及「盘前计划」列表里的代码 → `goSymbol(symbol)`，跳到本页并自动选中、滚动到走势图。
- 本页只读；录成交、导入、提交复盘后页签缓存失效，下次进入自动重取。
- 与统计页：本页已实现合计 = 统计页「净已实现」（同为 `t_trade.realized_pnl`，区间一致时）。
- 与账户页：本页不给浮动盈亏；持仓市值与浮盈在账户页按最新快照计算。
