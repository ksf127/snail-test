# 05 记成交（tab-trade）

> 页面位置：`static/index.html` → `<section id="tab-trade">`；前端函数 `loadTradeTab`、`loadPositions`、`loadTradeList`、`submitTrade`、`parseBatch`、`submitBatch`、`importFile`、`tradeRow`、`tradeQuery`；后端 `TradeController`、`TradeService`、`TradeImportService`。
> 数据链：成交流水 → 当前持仓 → 每日复盘 → 统计。**这页是所有盈亏数字的起点，录错这里，后面全部错。**

## 1. 这页回答什么（不回答什么）

回答：

- 今天/这段时间买了什么、卖了什么，成交价、数量、费用、理由是什么？
- 每笔卖出实际赚了多少（已实现盈亏），不是「卖价减买价」的毛差？
- 当前还持有哪些票，加权成本是多少，持仓成本金额多少？
- 这笔交易是计划内还是计划外，有没有关联盘前计划？

不回答：

- 未卖出的浮盈浮亏（需要每日复盘填收盘价，见 `06-review.md`）。
- 净值、回撤、胜率、盈亏比（统计页算，成交页只提供原始流水）。
- 为什么亏、该不该卖（理由字段只记录当时的判断，不判断对错）。

## 2. 数据来源与查询条件

| 数据块 | 接口或表 | 过滤条件 | 何时刷新 |
| --- | --- | --- | --- |
| 单笔录入 | `POST /trades` → `t_trade` | 无查询；`accountId` 为空按 1 | 点「记录成交」后清空价格/数量/费用/理由/卖出条件 |
| 当前持仓 | `GET /trades/positions` → `t_position` | `accountId` 可选；SQL 按 `account_id, symbol` 升序 | 进入页面、单笔/批量/导入成功后、切账户 |
| 区间成交 | `GET /trades` → `t_trade` | `from`、`to` 必填（含端点）；`accountId`；`keyword` 模糊匹配代码或名称；`side`；`isPlanned`；`pnl`；`sort`；`page`、`size` | 进入页面、改筛选、翻页、录入成功后回第 1 页 |
| 批量粘贴 | `POST /trades/batch` | 逐行调 `record`，单行失败不影响其他行 | 点「解析并提交」 |
| Excel / CSV | `POST /trades/import` | `.xlsx` 走 POI，其余按文本（UTF-8）；逗号或制表符分隔 | 点「上传导入」 |
| 导入模板 | `GET /trades/import/template` | 固定 10 列 + 2 行示例 | 点「下载 Excel 模板」 |
| 计划联动 | `t_trade_plan.status` | `planId` 非空且计划存在 | 成交保存事务内 |

筛选细节（后端 `TradeService.list`）：

- `size` 越界（<1 或 >200）回落 20；`page` <1 按 1。
- `pnl=WIN` 为 `realized_pnl > 0`，`LOSS` 为 `< 0`，`NONE` 为 `IS NULL`（买入一律落在 NONE）。
- 排序：默认 `trade_date DESC, id DESC`；`sort=pnl` 先按 `realized_pnl DESC`，再按日期、ID 倒序。
- 前端日期默认：`tt-from` 为今天减 29 天，`tt-to` 与 `tr-date` 为今天（首次进入时填充）。

## 3. 字段口径

| 字段 | 计算口径 | 来源 | 正常范围/参考 | 异常含义 |
| --- | --- | --- | --- | --- |
| 交易日期 `tradeDate` | 成交发生日，原样落库 | 表单 / 导入第 1 列 | ≤ 今天；补录允许过去日期 | 晚于今天会让统计区间错位 |
| 代码 `symbol` / 名称 `name` | 原样落库，不做行情校验 | 表单 / 导入第 2、3 列 | 6 位代码常见 | 代码大小写/空格不一致会拆成两个标的 |
| 方向 `side` | 统一转大写，只接受 `BUY`/`SELL` | 表单下拉 / 导入（买、B、买入均可） | 二选一 | 其他值被拒，整行不入库 |
| 价格 `price` | 成交单价，≥ 0.001 | 表单 / 导入第 5 列 | >0，3 位小数常见 | 填 0 或空被拒 |
| 数量 `quantity` | 正整数，股 | 表单 / 导入第 6 列 | >0；卖出 ≤ 当前持仓 | 卖出超持仓直接报错，不落库 |
| 费用合计 `fee` | 佣金+印花税+过户费，录入方填；空按 0 | 表单 / 导入第 7 列 | ≥0；小额常见 5.00 | 填 0 会高估盈亏；填负被拒 |
| 是否计划内 `isPlanned` | 空按 `true` | 表单「来源」/ 导入第 8 列 | 计划外才是少数 | 计划外占比高说明临场操作多 |
| 关联计划 `planId` | 可空；存在则把计划置 `EXECUTED` | 表单 / 接口 | 可空 | 计划不存在时成交照常，只是不更新状态 |
| 理由 `reason` | 必填非空，买入逻辑需可证伪 | 表单 / 导入第 9 列 | 一句话含依据与止损 | 留空被拒；写成「看好」无法复盘 |
| 卖出条件 `sellCondition` | 可空，买入时写下的退出条件 | 表单 / 导入第 10 列 | 可空 | 留空则卖出时无对照标准 |
| 账户 `accountId` | 空按 1 | 全局账户 / 接口 | 1、2… | 批量与导入不传账户，固定落 1 |
| 成交额 | `price × quantity` | 前端 `tradeRow` | 2 位小数 | 不含费用，不等于现金流 |
| 已实现盈亏 `realizedPnl` | 仅卖出有值：`price×qty − fee − avgCost×qty`，2 位四舍五入 | `TradeService.applySell` | 可正可负；买入为 `—` | 与毛差不等是正常的（费用+加权成本） |
| 加权成本 `avgCost` | 买入：`(原成本额 + price×qty + fee) ÷ (原数量+qty)`，4 位四舍五入；卖出不变 | `TradeService.applyBuy` | >0；清仓后行被删除 | 与最近买入价不同＝分批建仓或含费用 |
| 持仓数量 | 买入累加、卖出扣减；减到 0 删除该行 | `t_position` | ≥0（0 不存行） | 持仓表查不到＝已清仓或录到别的账户 |
| 持仓成本（页面列） | `avgCost × quantity`，前端 2 位 | 前端 `loadPositions` | ≈ 累计买入金额+费用 | 与「数量×最新价」混看会误判浮盈 |

口径铁律（代码写死，不可配置）：

- **买入费用摊进成本**，卖出时不再扣买入费；**卖出费用在卖出时直接扣**。
- 加权成本只保留 4 位小数，已实现盈亏保留 2 位；四舍五入均为 `HALF_UP`。
- 成本是「成交时点的快照」：后续补录更早的买入不会回溯重算已有卖出的 `realizedPnl`。

## 4. 分析步骤

录入前检查清单（每笔都过一遍）：

- [ ] 日期是**成交日**不是录入日，补录的按实际发生日填。
- [ ] 代码、名称与券商流水一致，代码前后无空格。
- [ ] 方向选对：卖出前先确认该账户该代码有足够持仓。
- [ ] 价格填**成交均价**（分笔成交先自行合并或分行录入）。
- [ ] 费用填**买卖双边实际合计**（最低 5 元佣金也要填，别留空）。
- [ ] 数量为整数股，卖出数量 ≤ 持仓数量。
- [ ] 理由写到「可被证伪」：依据 + 触发条件 + 止损位，不写情绪词。
- [ ] 卖出条件在买入时就写，卖出时可对照。
- [ ] 计划内/外选择正确；有 `planId` 时确认该计划确实存在。
- [ ] 当前全局账户是目标账户（批量/导入除外，它们固定写账户 1）。

分析步骤：

1. 先看「当前持仓」表：数量、加权成本、持仓成本、更新时间，确认账户与持仓状态。
2. 回到「区间成交」，把日期拉到本次录入日，核对刚录的一笔是否出现在第一行。
3. 卖出单重点看「已实现盈亏」列，与手工估算的毛差对比，差额应等于两边费用 + 加权成本差。
4. 用「方向 / 来源 / 盈亏」筛选逐个切片：先看 `LOSS` 的卖出，再看计划外。
5. 对每笔亏损，读「理由」列：理由与走势相反＝决策问题；理由对但未执行卖出条件＝执行问题。
6. 需要看某只票的全部痕迹时，点代码跳标的分析（`data-jump-symbol`）。
7. 发现持仓成本异常，先查该代码历史买入流水，再判断是费用漏填还是数量录错。
8. 批量导入后先看结果条：`失败` 行会带行号与原因，按行修完再重传，不要整批重来。

## 5. 带数字的案例

> 以下为示例数据，非真实交易。

账户 1，期初空仓、现金 180000.00。

| 步骤 | 操作 | 计算 | 结果 |
| --- | --- | --- | --- |
| ① 买入 | 1000 股 @10.80，费用 5.00 | 金额 10800.00；加权成本 (0+10800+5)÷1000 | `avgCost=10.8050`，数量 1000，持仓成本 10805.00 |
| ② 卖出 | 500 股 @11.20，费用 5.00 | 净回款 5600−5=5595.00；成本 10.8050×500=5402.50 | `realizedPnl=192.50` |
| ③ 卖出后 | 剩余 500 股 | 数量 1000−500；成本价不变 | 数量 500，`avgCost=10.8050`，持仓成本 5402.50 |
| ④ 清仓 | 500 股 @10.90，费用 5.00 | 净回款 5450−5=5445.00；成本 5402.50 | `realizedPnl=42.50`，持仓行被删除 |
| ⑤ 对账 | 现金变动 | −10805.00 + 5595.00 + 5445.00 | 现金 180235.00，已实现合计 235.00 |

自洽校验：

- 毛差口径 `(11.20−10.80)×500 = 200.00`，与 192.50 差 7.50 = 买入费摊到该笔 2.50（5.00×500/1000）+ 卖出费 5.00。
- 全周期：买入成本 10805.00，卖出净回款 11040.00，差额 235.00 = 192.50+42.50。
- 单笔收益率参考：192.50 ÷ 5402.50 = 3.56%，不是 200÷5400 的 3.70%。

## 6. 判读表

| 现象 | 结论 | 动作 |
| --- | --- | --- |
| 已实现盈亏 ≠（卖价−买价）×数量 | 正常，差额是双边费用与加权成本 | 别改成毛差，否则统计系统性偏高 |
| 加权成本 ≠ 最近一次买入价 | 分批建仓或买入费摊入 | 查该代码买入流水，确认数量与费用 |
| 卖出报错「没有持仓，不能卖出」 | 持仓不存在：漏录买入，或录到了别的账户 | 切账户核对，补录买入后重试 |
| 卖出报错「卖出数量超过持仓」 | 数量多输、或买入数量少录 | 查流水后补录买入，不要拆成两条卖出绕过 |
| 区间成交有记录、持仓表没有 | 已清仓（数量归零删行） | 正常；去统计页看已实现结果 |
| 计划外交易的亏损笔数明显多于计划内 | 临场决策质量低于计划决策 | 去统计页对比两组胜率与盈亏比 |
| 费用列大量为 0 或「—」 | 录入漏费用，盈亏被高估 | 按券商流水补录费用（当前无编辑接口，需改库后重录） |
| 华泰/中信两账户下同一代码持仓两行 | 选了「全部账户」，持仓按账户分开 | 正常现象；持仓表无账户列，需切账户看 |
| `NONE` 筛选后全是买入 | 已实现盈亏只有卖出才有 | 正常；买入不参与胜率统计 |
| 导入结果显示部分失败 | 单行校验未过（日期/方向/理由/数量） | 按提示行号修单行，再重新上传 |

## 7. 数据前提与常见问题

- **无编辑/删除接口**：成交录错只能改库或补一笔反向记录，补反向记录会污染胜率与笔数。
- **补录顺序影响成本**：先录卖出再录更早的买入会因「没有持仓」失败；导入按文件行顺序执行，历史数据必须买入在前。
- **补录不回算历史**：`realizedPnl` 在卖出当时算定，之后补录更早买入或改费用都不会更新它，页面与直觉不一致时以流水为准。
- **批量与导入固定写账户 1**：前端 `parseBatch` 不发送 `accountId`，后端空值按 1 处理；选着账户 2 导入也会落到账户 1。
- **CSV 只按逗号/制表符切分**：名称或理由里带逗号会错列；GBK 编码会乱码（按 UTF-8 读）。
- **导入校验比单笔更严**：批量接口不走 `@Valid`，但 `TradeImportService.validate` 要求理由非空、日期可解析、方向可识别。
- **计划 ID 不存在不拦截**：成交照常写入，只是计划状态不变，`planId` 仍留在流水上。
- **日期区间反了不报错**：后端 `between` 直接返回空列表，页面显示「筛选条件下没有成交」。
- **持仓表时间列**：`updated_at` 只在买入或卖出未清仓时刷新，清仓即删行，时间无法回溯。

## 8. 联动

- **统计页胜率/盈亏比**：分母是区间内 `side='SELL' AND realized_pnl IS NOT NULL` 的记录；买入再多也不进分母。
- **跨日持仓的归属**：一笔卖出若对应多日买入，全部盈亏落在**卖出日**，统计区间按卖出日切。
- **统计·净已实现**：`SUM(realized_pnl)`（卖出），与这里每笔已实现盈亏之和一致。
- **标的分析**：买入额 = `price×qty+fee`，卖出额 = `price×qty−fee`，已实现盈亏直接求和；所以这里费用填错会同时污染标的页。
- **标的涨跌幅**：不取自成交价，而取每日复盘写入的收盘价快照；成交页不参与。
- **每日复盘**：复盘页的持仓行来自 `t_position`，这里没录买入，复盘就没有该标的可填收盘价，净值会被低估。
- **账户页**：持仓市值与浮动盈亏同样来自复盘快照，不是用 `avgCost` 实时算的。
- **计划页**：带 `planId` 的成交会把计划状态改为 `EXECUTED`，计划页相应行不能再取消。
