# 交易复盘 · 每页分析说明

这份文档按页面写，每个页面统一回答四件事：

1. **这页用来回答什么问题**（不解决什么）
2. **分析步骤**（打开后按什么顺序看）
3. **怎么下结论**（什么现象对应什么判断、下一步做什么）
4. **数据前提与口径**（为什么可能是空的、为什么和别的页对不上）

数据链路固定为：

```
盘前计划 → 记成交（流水）→ 每日复盘（净值 + 纪律）→ 统计 / 标的 / 账户（结论）
```

前三步是录入，后三页是分析。**分析页为空，先查录入，不要怀疑页面。**

> 每个页面标题下方都有一个可展开的「本页分析说明」面板，内容是本文件对应章节的现场版（这页回答什么、分析步骤、怎么判读、数据前提、字段口径、示例、联动）。不打开文档也能直接看到要点。

## 0. 全局规则（先读这一节）

### 0.1 全局账户选择器

页面右上角的下拉框是全局筛选，影响：

| 页面 | 是否受影响 | 说明 |
| --- | --- | --- |
| 账户与资金 | 是（高亮当前账户） | 列表仍展示全部账户，点卡片即切换 |
| 统计总览 | 是 | 成交、净值、标的、收益结构、原因全部按账户过滤 |
| 标的分析 | 是 | 同一只票跨账户合并为一行 |
| 记成交 | 是 | 持仓、区间成交只看该账户；新成交写入该账户 |
| 每日复盘 | 是 | 净值与持仓快照写入选中的账户 |
| 盘前计划 | 否 | 计划是想法，不绑定资金账户 |

选「全部账户」时：成交跨账户合并，净值按日期求和，持仓按代码合并。
**纪律违背永远不按账户过滤**——它衡量的是「人」当天的执行。

### 0.2 两种「筛选」不要混

| 类型 | 包括 | 改变后发生什么 |
| --- | --- | --- |
| 全局查询条件 | 顶部日期区间、全局账户 | 重新请求接口，整页重算 |
| 表格内筛选 | 关键字、方向、盈亏正负、排序、每页条数、板块涨跌 | 只在已取回的数据里本地过滤，不改查询、不影响图表 |

统计总览页所有卡片都吃第一类条件；各页的日期又相互独立（标的分析有自己的日期，计划/成交/复盘按表单日期，账户页展示全部历史）。

## 1. 账户与资金（tab-accounts）

### 1.1 这页回答什么

- 现在有几个账户，各自还有多少钱？
- 哪个账户在赚钱、哪个在拖后腿？
- 仓位多重、浮盈有没有落袋？

它**不回答**：为什么亏、哪只票亏的（去统计总览 / 标的分析）。

### 1.2 分析步骤（5 分钟）

1. 看顶部 8 个 KPI：**总权益 → 现金 → 持仓市值**，先确认总仓位百分比。
2. 扫一遍账户卡片：比较各账户的**收益率、已实现、浮动、卖出胜率**。
3. 看「账户净值对比」：曲线是否同向、谁的波动更大。
4. 需要细看某个账户时，**点它的卡片**，全站切换到该账户，再进统计总览。

### 1.3 怎么下结论

| 现象 | 说明什么 | 下一步 |
| --- | --- | --- |
| 现金占比 < 10% | 满仓甚至融资，回撤会被放大 | 看净值曲线最大回撤，考虑降仓位 |
| 已实现为正、浮动为大额负数 | 赚的钱没落袋，浮盈在回吐 | 去标的分析看是哪只票，检查止盈纪律 |
| 收益率高但卖出胜率低 | 靠少数大赚覆盖多数小亏 | 看盈亏比与最大单笔亏损是否可承受 |
| 某账户曲线长期跑输其它账户 | 可能是账户用途不同（试错仓/主仓），也可能是该账户执行更差 | 切到该账户看计划内外胜率差 |
| 卡片里的「持仓·成交」与记成交页对不上 | 持仓快照过期或成交录到了别的账户 | 切到该账户核对流水，补当天复盘 |

### 1.4 数据前提

- 「总权益 / 现金 / 持仓市值」来自**每日复盘**写入的资金快照；没提交过复盘，显示 0 或 —。
- 「浮动盈亏」只覆盖有持仓快照的标的，不是全市场实时价。
- 新建账户时填了初始资金，会立刻写入当天一条净值（`equity = cash = 初始资金`），所以当天就有数据。

### 1.5 联动

- 点 KPI「总权益」→ 统计总览看区间收益。
- 点 KPI「已实现盈亏」→ 收益结构。
- 点账户卡片 → 全站切换账户（最常用入口）。
- 点「持仓只数」→ 标的分析。

## 2. 统计总览（tab-overview）

### 2.1 这页回答什么

- 这段时间整体赚了还是亏了？回撤多深？
- 钱是靠什么赚的、亏在什么动作上？
- 按计划做和不按计划做，差多少？
- 纪律问题集中在哪一条？

这是主分析页，**自上而下就是推荐的分析顺序**：结果 → 结构 → 原因 → 曲线 → 对比 → 执行。

### 2.2 查询口径

点「拉取统计」会并发请求下面这些接口，全部带同一组 `from/to` 和全局账户：

| 卡片 | 接口 | 数据来源 |
| --- | --- | --- |
| KPI | `/stats/overview`、`/stats/equity`、`/stats/performance` | 成交 + 每日净值 + 复盘违背 |
| 收益与亏损结构 | `/stats/performance` | 区间卖出流水 |
| 亏损原因 | `/stats/reasons` | 区间卖出理由 + 已实现盈亏 |
| 净值曲线 | `/stats/equity` | `t_account_daily` |
| 月度收益 | `/stats/monthly` | 月度聚合成交 |
| 成交明细 | `/stats/trades` | `t_trade` |
| 计划内/外 | `/stats/overview` | 同区间成交按 `is_planned` 分组 |
| 板块参考 | `/refs/sectors` | `t_sector_daily` |
| 按月纪律违背 | `/stats/overview` | `t_discipline_violation` |

成交明细与板块表格内部的筛选只作用于该表格。

### 2.3 KPI 行

| KPI | 怎么算 | 判读要点 |
| --- | --- | --- |
| 区间收益 | 区间末净值 / 区间首净值 − 1 | 含浮动；净值点少于 2 个时显示 — |
| 已实现净收益 | Σ 卖出 `realized_pnl` | 只看落袋；为负说明平仓整体亏损 |
| 已实现盈利 / 亏损 | 正收益合计 / 负收益绝对值合计 | 两者相减 = 净收益；比例决定盈亏结构 |
| 最大回撤 | 相对此前峰值的最大跌幅 | 决定这套做法能不能长期承受 |
| 计划内胜率 | 计划内平仓盈利占比 | 与计划外对比才有意义 |
| 计划外胜率 | 同口径 | 低于计划内越多，临时起意的代价越大 |
| 已实现盈亏比 | 平均盈利 / 平均亏损绝对值 | >1 才可能靠「大赚小亏」覆盖低胜率 |
| 纪律违背 | 复盘勾选次数合计 | 只计数，不做主观加权 |

**组合判读**：

| 组合 | 结论方向 |
| --- | --- |
| 区间收益为负 + 净收益为负 + 回撤大 | 不是运气问题，是仓位与止损同时失控 |
| 区间收益为正 + 净收益为负 | 靠浮盈撑着，实际平仓在亏钱，落袋能力差 |
| 胜率 > 50% + 盈亏比 < 1 + 净收益为负 | 小赚多次、大亏一次，先砍最大单笔亏损 |
| 胜率 < 40% + 盈亏比 > 2 | 低频大赚模式，重点是控制连续亏损次数与回撤 |
| 计划内胜率明显高于计划外 | 临场发挥在拖累系统，收紧「计划外」额度 |

### 2.4 收益与亏损结构（#card-pnl）

**看什么**：环形图对比盈利金额与亏损金额；右侧 10 个指标（盈利/亏损笔数、胜率、盈利/亏损合计、平均盈利/亏损、盈亏比、最大单笔盈利/亏损）。

**分析步骤**：

1. 先看环形两段的比例，判断「赚的钱够不够填亏的坑」。
2. 再看平均盈利 vs 平均亏损：比值 < 1 说明每笔赢面不够。
3. 最后看最大单笔亏损：它往往就是某一条纪律失守的直接代价。

**结论示例**：平均亏损是平均盈利的 3 倍 → 止损形同虚设，去亏损原因里找「未止损/扛单」类理由。

### 2.5 亏损原因分析（#card-reason）

**看什么**：

- 柱状图：按卖出理由归类的已实现盈亏（正绿负红）。
- 明细表：每类理由的卖出笔数、盈亏笔数、胜率、盈亏合计、平均每笔。
- 亏损标的 Top 5：可直接点代码跳到标的分析。

**分析步骤**：

1. 先按「盈亏合计」从负到正排序，锁定最亏的一类理由。
2. 再看这一类「出现次数是否也多」：次数多 + 平均每笔为负 = 习惯问题；次数少但金额巨大 = 单次失控。
3. 点进亏损标的 Top，看是同一只票反复亏，还是分散亏。

**判读表**：

| 现象 | 结论 | 动作 |
| --- | --- | --- |
| 「未记录原因」占比高 | 不是原因分析没价值，是录入质量不够 | 先补卖出理由，再谈分析 |
| 某一类理由胜率 < 30% 且笔数最多 | 这是当前最大漏损点 | 下一周期只改这一条 |
| 单类理由只有 1~2 笔但亏损最大 | 极端交易，不是系统问题 | 找到那笔成交，回看当时情境 |
| 盈利理由里有一类金额特别大 | 你的优势在这里 | 提高它的仓位与重复率，而不是换打法 |

### 2.6 账户净值曲线

**看什么**：原始净值序列（不平滑、不补点），首末点有标记，点数多时可缩放。

**分析步骤**：

1. 找最大回撤区间：从哪天开始跌、跌了多久、多久修复。
2. 看曲线形状：台阶式上升（稳定）还是深 V（靠行情）。
3. 对照成交明细，确认回撤期间是否伴随交易频率上升。

**判读**：回撤「深度」决定风险承受，「修复时间」决定策略是否可持续。修复时间越来越长，通常意味着做法与当下市场不匹配。

### 2.7 月度收益（环比 / 同比）

每个月一根柱，环比对比上月、同比对比去年同月，单位是百分点。

**判读**：

- 单月亏损正常，**连续 3 个月为负**才说明方法失效。
- 环比大起大落说明收益依赖少数交易，不是稳定系统。
- 同比只在有跨年数据时才有参考价值。

### 2.8 成交明细

**看什么**：区间内全部成交流水，支持关键字、方向、计划内外、盈亏正负、排序、分页。表头灰底居中加粗，结果行隔行底色。

**分析步骤**：

1. 按「已实现盈亏」排序，看最赚与最亏的几笔。
2. 点代码跳标的分析，确认这笔在整段走势里的位置。
3. 用「计划外」筛选，抽查这些交易当时有没有写理由。

**用途**：它是从「单笔」到「单票规律」的入口，也是核对录入是否完整的底表。

### 2.9 计划内 / 计划外对比

两组分别给胜率、盈亏比、平仓笔数。

**判读**：

| 对比结果 | 结论 |
| --- | --- |
| 计划内胜率、盈亏比都更高 | 计划有效，问题在执行率 |
| 计划内笔数远少于计划外 | 你大部分时间在做计划外的事，先提高计划覆盖率 |
| 两组差不多 | 计划没有提供额外信息，计划质量本身要改 |
| 计划外反而更好 | 计划过于保守，或只在行情好时才敢按计划做（样本偏差，需看区间） |

这是全系统最核心的一组对照：两组之差 = 「有没有按计划做」的量化代价。

### 2.10 板块参考 · 银行

**看什么**：中证银行（399986）走势 + 账户净值，同区间、同账户。

**注意**：上面的曲线跟随顶部区间；下面的明细表只是区间内交易日的明细，可单独筛选/翻页，**不会改变图表**。

**判读**：

- 板块涨、账户不涨：不是逆势，是选股或节奏问题。
- 板块跌、账户跌更多：仓位或标的选择放大了风险。
- 板块横盘、账户大幅波动：收益来自频繁交易，需重点看费用与胜率。

它只是外部参照，不参与任何盈亏计算。

### 2.11 按月纪律违背

**看什么**：按月统计 7 类纪律违背的次数分布。

**分析步骤**：

1. 不要只看总数，找**连续月份反复出现**的那一条。
2. 对照计划内/外胜率差，确认这条纪律是否真的在造成亏损。
3. 下个周期只承诺改一条，下月回来看它是否下降。

**判读**：违背次数下降但收益没变，说明问题不在纪律；次数和亏损同时下降，才说明改对了。

## 3. 标的分析（tab-symbols）

### 3.1 这页回答什么

- 钱是哪几只票赚的、哪几只拖累的？
- 同一只票，买卖点踩得对不对？
- 哪些票买了没卖、哪些已清仓？

它**不回答**：整体仓位是否合理（去账户页）、纪律执行（去统计页）。

### 3.2 分析步骤（10 分钟）

1. **先看贡献柱**：收益是集中在 1~2 只票，还是分散。
2. 用明细表按「已实现盈亏」排序，从上往下看前 3 名与后 3 名。
3. 点开亏损最多的那只，看走势图上的买卖点位置。
4. 回成交明细核对：亏损是因为买错位置，还是因为没止损。

### 3.3 判读表

| 现象 | 说明 | 下一步 |
| --- | --- | --- |
| 前 2 只票贡献 > 70% 收益 | 收益集中，复制性存疑 | 看这两笔是计划内还是计划外 |
| 多数票小亏、少数票大亏 | 止损不统一 | 去亏损原因找「未止损」类理由 |
| 买点在下跌段、卖点在上涨前 | 追涨杀跌 | 检查计划里的触发条件是否被跳过 |
| 买卖点在同一价位反复出现 | 区间内来回挨打 | 减少交易频率，设更宽的止损/止盈 |
| 有持仓但区间无成交 | 长期不动或忘记记录 | 去每日复盘确认收盘价与止盈止损 |
| 区间涨跌幅为正、已实现为负 | 拿不住，赚小钱跑、亏钱扛 | 重点看卖出理由分布 |

### 3.4 口径提醒

- 标的来源取三处并集：区间有成交、区间有持仓快照、当前仍持仓。只看成交会漏掉「买了没卖」，只看持仓会漏掉「区间已清仓」。
- 区间涨跌幅只反映价格，与你的买卖时点无关；已实现盈亏才反映操作结果。
- 选「全部账户」时同一只票跨账户合并；想看单账户请先切账户。

### 3.5 联动

- 从成交明细、持仓、计划、亏损 Top 点代码，都会落到这里并自动选中。
- 页内点击表格行切换单标的走势。

## 4. 盘前计划（tab-plan）

### 4.1 这页回答什么

- 今天准备做什么？触发条件写清楚了吗？
- 这次交易属于计划内还是临时起意？

### 4.2 什么算一份合格的计划

逐项检查，缺一项就补：

| 要素 | 合格标准 | 不合格示例 |
| --- | --- | --- |
| 触发条件 | 可量化、可判断真假（价格/均线/开盘表现） | 「感觉要涨」 |
| 动作 | 买/卖、价格区间、数量或仓位比例 | 「关注一下」 |
| 理由 | 一句话说明为什么现在做 | 「别人都在买」 |
| 放弃条件 | 什么情况下今天不做 | 缺失（只能做，不能不做） |
| 日期 | 只对当天有效 | 长期挂着不处理 |

### 4.3 分析用法

- 计划状态「待触发 → 已执行 / 已取消」是纪律的一部分：**执行率低**说明计划脱离实际，**取消率高**说明条件设得太宽。
- 记成交时关联计划，统计页的「计划内/计划外」才有意义；没关联的记录默认按 `is_planned` 标记。
- 点代码可跳到标的分析，先看走势再定条件。

### 4.4 数据前提

计划不绑定资金账户，切换全局账户不会过滤计划；它按计划日期查询。

## 5. 记成交（tab-trade）

### 5.1 这页回答什么

- 今天实际做了什么？流水是否完整？
- 当前持仓的成本与数量对不对？

流水是全系统唯一事实来源：持仓、已实现盈亏、胜率、原因分析都由它推导。

### 5.2 录入前的检查清单

| 检查项 | 为什么 |
| --- | --- |
| 日期正确 | 归属到错误的日期会打乱月度与区间统计 |
| 账户正确 | 选「全部账户」时按默认账户写入，容易记错账 |
| 方向正确 | 买卖反了会让持仓与已实现盈亏全错 |
| 价格/数量/费用 | 成本与已实现盈亏的基础 |
| 计划内 / 计划外 | 决定统计页两组对比 |
| 卖出理由 | **卖出必填**；不写会归入「未记录原因」，直接削弱原因分析 |
| 买入时写卖出条件 | 没有卖出条件的买入，等于没有止损计划 |

### 5.3 当前持仓怎么看

- 加权成本：判断卖点的基准，不是「回本价」的心理锚。
- 成本金额与账户页「持仓市值」对照：差异大说明快照过期（当天复盘没提交）。
- 数量为 0 的持仓应已清仓，不应留在表中。

### 5.4 批量 / Excel 导入

先解析预览，再提交；失败行单独列出（行号 + 原因），不会整批丢掉。导入前确认账户，导入后抽查 2~3 行与券商流水核对。成交流水、每日资金、当前持仓三类都走「导入」页统一入口，字段与去重规则见 [07-import.md](pages/07-import.md)。

### 5.5 区间成交

与统计页同一套筛选与分页，用于录完立刻核对：笔数、买卖金额、已实现盈亏是否与券商一致。

### 5.6 联动

- 点代码 → 标的分析。
- 录完卖出理由 → 统计页「亏损原因分析」立即有数据。

## 6. 每日复盘（tab-review）

### 6.1 这页回答什么

- 今天净值为什么变？执行得怎么样？
- 明天要改哪一条？

它是唯一同时产出**净值**与**纪律**的页面：统计页的回撤、收益、纪律分布都依赖这里。

### 6.2 记录方法（按顺序）

1. 写事实：大盘、强势方向、弱势方向。只写看到的事实，不写判断。
2. 写错过：看到但没做的机会 + 原因（这是复盘的黄金素材）。
3. 写情绪：今天有没有因为情绪做决定。
4. 写经验：**只写一条**最重要的，写多了等于没写。
5. 写明日待办：具体到「什么条件做什么」。
6. 填持仓收盘价、止损位、止盈位、买入逻辑是否仍成立。
7. 勾选纪律违背。
8. 提交。同一天重复提交视为修改，不会产生两条净值。

### 6.3 净值怎么来的

系统用「现金 + Σ(持仓数量 × 收盘价)」自动计算净值；只有券商结算价与手工价不一致时才手填。
不要漏填现金——现金漏掉会让净值偏低、回撤算错，整个统计页跟着失真。

### 6.4 纪律自检 7 项

盘中改计划、计划外交易、追涨杀跌、听消息下单、亏损加仓、超仓位上限、盯盘过频。

**勾选原则**：只要当天发生过就勾，不管赚没赚钱。用结果反推纪律，等于自欺欺人。

### 6.5 判读表

| 现象 | 说明 | 动作 |
| --- | --- | --- |
| 连续多天勾「计划外交易」 | 计划覆盖不足或执行失控 | 次日减少计划外额度，先做计划内 |
| 「亏损加仓」反复出现 | 在跟市场较劲 | 设硬性规则：亏损仓位不加仓 |
| 净值下降但纪律项为 0 | 是市场/选股问题，不是执行问题 | 去看板块与标的分析 |
| 净值上升但纪律项很多 | 靠运气赚钱，风险在累积 | 不要因为赚钱就放过纪律 |
| 复盘记录只有一句话 | 复盘质量不足 | 至少补齐「错过机会 + 一条经验」 |

### 6.6 数据前提

- 当天没提交复盘 → 净值序列缺一天，回撤与区间收益按实际有点的日子计算。
- 「读取」历史只回填记录文本，纪律明细需重新勾选，避免误覆盖。

## 7. 一键导入（tab-import）

### 7.1 这页回答什么

- 券商导出的成交流水、每日资金、当前持仓，怎么一次入库？
- 系统把哪一列认成了什么字段，有没有识错？
- 哪些行会写入、哪些行重复被跳过、哪些行有问题？

它**不回答**：行情数据、盘前计划、复盘文本。

### 7.2 三种导入类型

| 类型 | 入库表 | 重复处理 |
| --- | --- | --- |
| 成交流水 | `t_trade`（走 `TradeService.record`，同步维护持仓与已实现盈亏） | 按日期+代码+方向+价格+数量查重，默认跳过 |
| 每日资金 | `t_account_daily` upsert | 同账户同日期覆盖 |
| 当前持仓 | `t_position` 按代码覆盖；有最新价时写 `t_position_daily` | 同账户同代码覆盖 |

成交必须走与手工录入同一套成本逻辑，否则会出现两套成本价；持仓只覆盖当前状态，不回推成交。

### 7.2.1 自动同步（定时扫下载目录）

券商网页没有对外接口，系统不保存账号密码、也不调私有接口。做法是**定时扫下载目录自动入库**，华泰 / 东方财富 / 同花顺通用。

- 交易日 **09:35、11:35、13:05、15:05** 各扫一次（开盘、午间、下午开盘、收盘）。
- 默认扫 `~/Downloads`，配置项 `trade-journal.sync.directories`；券商下载位置不同就改这里。
- 按文件内容 SHA-256 去重：同一份文件导出多次只处理一次；内容变了会重新解析，重复成交逐行跳过。
- 类型先按文件名关键词认，认不出再按表头试解析；都认不出记「已跳过」，不猜着导。
- 页面顶部有「立即扫描并导入」可手动触发，下面列出最近处理过的文件与结果。

### 7.2.2 自动下载（到点自己点导出）

自动同步省掉「上传」，自动下载再省掉「下载」：到点用本机 Chrome 打开券商导出页，点导出，落盘后立即入库。

- 交易日 **09:33、11:33、13:03、15:03** 执行，比扫描早 2 分钟；下载成功会立刻触发一次扫描。
- 复用你手动登录后的 Cookie，不保存账号密码；登录态在 `~/.trade-journal/browser/<券商名>`。
- 页面地址和点击步骤写在 `trade-journal.download.brokers[].steps`；页面改版只改配置。
- 首次使用：卡片里选券商 →「打开浏览器登录」→ 关闭窗口 →「立即下载并导入」验证。
- 单个券商失败只影响自己，失败原因显示在「说明」列；表格里能看到每个券商的状态与落盘文件数。
- 详细步骤语法、接口和排查看 [pages/07-import.md](pages/07-import.md) 第 12 节。

### 7.3 分析步骤

1. 选类型（三者可分三次导）→ 选账户（默认跟随全局账户）。
2. 拖入 `.xlsx` / `.csv` / `.txt`，或直接从 Excel 复制粘贴。
3. 看预览四个数字：**数据行 / 可导入 / 已存在 / 有问题**。数据行明显偏少＝表头没认对。
4. 核对「列识别 chips」，出现「（未识别）」的必填列先回 Excel 改列名。
5. 确认导入，然后去记成交抽查首尾两笔、去账户页核对持仓。

### 7.4 怎么判读

| 现象 | 说明 | 动作 |
| --- | --- | --- |
| 必填列显示「未识别」 | 表头没有关键词，或用了合并单元格 | 整理成单行表头后重新解析 |
| 「已存在」数量多 | 同一份文件导过，或增量区间重叠 | 确认后选「跳过」，只写新行 |
| 少量「有问题」 | 多为合计行、备注行 | 正常，不用改；真实数据行按行号回 Excel 修 |
| 每日资金同日重复 | 系统按日期覆盖 | 后导的为准，不会叠两条 |
| 导入后持仓偏高 | 文件缺卖出记录 | 补齐卖出区间再导，系统按日期升序重放 |
| 导入后统计页没变 | 其它页签缓存旧数据 | 切到统计页点「拉取统计」，或切换一次账户 |

### 7.5 数据前提

- 表头包含关键词即可，列顺序无所谓；单次最多 2000 行。
- 文本编码自动识别 UTF-8 / GBK，分隔符自动识别逗号与制表符。
- `.xls` 老格式不支持，请另存为 `.xlsx`。
- 导入不校验行情；代码大小写/空格不一致会被当成两个标的。
- 详细字段口径、去重计数规则与完整案例见 [pages/07-import.md](pages/07-import.md)。

### 7.6 联动

- 成交 → 统计总览、标的分析、亏损原因。
- 每日资金 → 账户净值、回撤、区间收益。
- 当前持仓 → 持仓市值、复盘预填。

## 10. 推荐分析节奏

### 10.1 每日（收盘后 15 分钟）

1. 记成交（补当天流水与卖出理由）。
2. 每日复盘（净值、持仓收盘价、纪律）。
3. 统计总览只看两件事：净值是否异常、纪律勾了几条。

### 10.2 每周（30 分钟）

1. 统计总览：近 7 天 KPI + 净值曲线。
2. 收益结构 + 亏损原因：找出一类要改的理由。
3. 计划内/外对比：算这周「临时起意」的代价。

### 10.3 每月（1 小时）

1. 月度收益环比、最大回撤、连续亏损次数。
2. 按月纪律违背：找反复出现的那条。
3. 标的分析：前 3 名与后 3 名的买卖点复盘。
4. 账户页：分账户对比，决定资金是否调仓。

### 10.4 每季度（半天）

1. 账户净值对比 + 回撤修复时间。
2. 计划执行率与计划外占比。
3. 只保留一条最有效的做法，删掉一条最亏的习惯。

## 11. 常见问题

**Q：统计页为什么全是 0 / 空？**
A：区间内没有成交或没有复盘净值。先确认区间、账户是否选对，再看记成交与每日复盘是否提交。

**Q：净值点数很少？**
A：净值由每日复盘写入，只有提交过复盘的交易日才有点。

**Q：为什么区间收益和已实现净收益对不上？**
A：区间收益含浮动盈亏，已实现只算卖掉落袋的部分，差额就是当前浮盈浮亏。

**Q：为什么某只票在标的分析里有、成交明细里没有？**
A：标的来源取成交、持仓快照、当前持仓三处并集；它可能只有持仓快照。

**Q：为什么板块曲线的日期比区间短？**
A：板块行情只有实际交易日的数据，没有的日期不会补点；表格也只在区间内展示。

**Q：切换账户后数据没变？**
A：先确认新成交/复盘是否写入该账户；「全部账户」是合并视图，和单账户结果本来就不同。
